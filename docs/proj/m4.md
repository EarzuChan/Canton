> - **从此可交互，双轨验收**：无头回归继续守住渲染与确定性像素基线；本期起真窗口交互跑通，主人的验收以亲手把玩窗口、模态、自绘标题栏、跨屏 DPI 和中文输入法为准，辅以自动化单测与端到端用例。
> - **一口气做完**：按章节顺序推进，不设中途验收点。只有遇到本文件没定、又影响公开接口或范围的事才停下来问主人。

> - **严守分层与编译期物理剥离**：`win32`、`d3d11` 只依赖 `core`；`CANTON_ENABLE_DEV` 只出现在构建接线与 `host/`（及必要的顶层装配入口），Dist 宿主物理不含 HMR、Live、诊断浮层、`DiagnosticsOverlay` 与调试快捷键。
> - **命名不带里程碑编号**：新增文件、夹具与测试按内容命名；进度与实测决定记在本文件文末“施工笔记”。

## 0. 已定口径

- **唯一应用入口与全仓清零 `createApp`**：
  - 用户入口统一默认导出 `appBuilder(Root).build()` 的应用定义（如 `export default appBuilder(App).build()`），不再由脚本侧手动调用 `.mount()`；Live 与 Dist 宿主都在模块求值完成后读取入口模块的 `default` 导出并启动应用。
  - 删除 `createApp`、`CantonApp` 及单视口隐式根挂载路径，**不在内部保留单树偷懒辅助**；`tests/runtime/*.test.ts`、`tests/fixtures/*` 与 `native-tests/` 里经脚本挂载的用例一律迁移到 `appBuilder` + `<App>` + `<Window>`。
- **`<App>`、`<Window>`、`WindowState` 与 Handle 的职责切分**（按 ADR 003 / 004 对齐 Compose Desktop）：

  | 原语 / 对象 | 归属与生命周期 | 承载字段与能力 |
  | --- | --- | --- |
  | `appBuilder(Root)` | 入口装配器 | `.provide(key, value)`、`.arrangable(name, def)`、`.build()`（产出供宿主启动的不可变应用定义）。 |
  | `<App>` | 进程唯一非布局根，不建画区、不产 `LayoutNode` | Props：`exitOnLastWindowClosed?: boolean`（默认 `true`）、`appId?: string`（非空时在开窗前调 `SetCurrentProcessExplicitAppUserModelID`）、`icon?: string`（资产路径，WIC 解码为进程默认 `HICON`）。默认槽交付 `&app-handle`：`exitApplication(): void`。 |
  | `<Window>` | 声明式窗口原语，存在即打开、移出即销毁；向子树建立画区作用域并独立 `provide` `Density` 与 `FocusManager` | Props：`state?: WindowState`（缺省内部自建）、`onCloseRequest: () => void`（必填）、`title?: string`（默认 `''`）、`icon?: string`（覆写 `<App :icon>`）、`visible?: boolean`（默认 `true`，隐藏不卸载组合树）、`minSize?: { width: Dp; height: Dp }`、`maxSize?: { width: Dp; height: Dp }`、`owner?: 'auto' | 'none'`（默认 `'auto'`）、`modality?: 'none' | 'owner' | 'application'`（默认 `'none'`）、`chrome?: 'system' | 'customTitleBar' | 'frameless'`（默认 `'system'`）、`role?: 'standard' | 'utility'`（默认 `'standard'`）、`resizable?: boolean`、`minimizable?: boolean`、`maximizable?: boolean`、`closable?: boolean`（均默认 `true`）、`alwaysOnTop?: boolean`（默认 `false`）、`showInTaskbar?: boolean`（可选覆写 ADR 004 默认联动）、`backdrop?: 'none' | 'mica' | 'micaAlt' | 'acrylic'`（默认 `'none'`）、`cornerPreference?: 'default' | 'round' | 'roundSmall' | 'square'`（默认 `'default'`）。 |
  | `WindowState` | `createWindowState(init?)` 创建，可长于单次挂载；同一实例同时绑多个活跃 `<Window>` 直接报错，卸载后保留快照 | 双向同步几何形态：`size`（客户区 `{ width: Dp; height: Dp }`，默认 `960.dp × 640.dp`）、`position`（`'platformDefault' | 'centerScreen' | 'centerOwner'` 或 `{ x: number; y: number }` 物理虚拟屏幕像素，默认 `'platformDefault'`）、`placement`（`'normal' | 'minimized' | 'maximized' | 'fullscreen'`，默认 `'normal'`）；只读运行期观测：`focused: boolean`、`dpiScale: number`；控制命令：`activate(): void`、`requestClose(): void`（走 `onCloseRequest` 同一路径）。 |
  | `WindowHandle` | `<Window>` 默认槽经 `&window-handle` 交付，绑死本次挂载，不进公开 `provide` | 只读 `state: WindowState`；自绘标题栏非客户区 Modifier 构造器：`draggableArea()`、`nonDraggableArea()`、`captionButton('minimize' | 'maximize' | 'close')`（返回普通 Modifier 片段，用在窗口画区之外报错）。 |

- **画区作用域自然分界**：只有在 `<Window>` 建立的画区作用域内才允许挂载 `<Layout>` 及基于它的自绘组件（`<Box>`、`<Row>`、`<Column>`、`<Text>`、`<Input>` 等）；直接写在 `<App>` 下或画区外时直接报错。`<Window>` 对祖先布局透明，嵌套在其他 `<Window>` 的子树内只是为了继承组合生命周期与默认 Win32 `owner`（除非显式写 `owner="none"`），不向父窗 `LayoutTree` 插入节点。
- **私有窗口身份**：不向 TS 暴露裸 `HWND` 或数字/字符串 `WindowId`。桥接层以私有 `WeakMap` 维护 `WindowState` / `WindowHandle` 到进程内单调不复用的私有整数窗口句柄，窗口销毁即从原生活跃表摘除（一并为 M7 `CallContext::lookupHwnd` 铺平）。
- **`1 VM : N 原生表面` 的运行时拓扑**：
  - 进程单 UI Owner 线程运行唯一 `QuickJsScriptHost`；每个活跃 `<Window>` 对应一套独立的窗口会话（独立 `NativeScene`、`SceneFramePipeline`、`InputSession`、`InputTextSession`、窗口级 `DiagnosticsOverlay` 与 `d3d11::RenderTarget`），所有窗口共享同一 `d3d11::Renderer`（GPU 设备、字形与路径图集、纹理缓存）与同一 `FontRegistry` / `DWriteTextMeasurer`。
  - VBlank 节拍按需驱动有待办工作的窗口出帧，全部窗口空闲时停表零空转。
  - **末窗退出与同帧切窗**：`exitOnLastWindowClosed` 仅在一次完整重排事务提交收尾后、且本次应用会话曾成功打开过至少一个窗口的前提下，活跃窗口数降为 `0` 时触发有序退出；同帧销毁登录窗并打开主窗绝不误退。
  - **0 窗错误屏兜底**：启动装配报错、Live DevServer 不可达、模块求值异常，或运行期挂起时若当前没有任何可见应用窗口，宿主自动以单兜底窗显示错误屏（并保持 Live 重连/热更恢复能力，恢复并挂载真实 `<Window>` 后收起兜底窗）；已有窗口打开时直接在现有窗口上显示错误屏。
- **Per-Monitor V2 DPI**：
  - 每窗独立通过 `GetDpiForWindow` 取初始倍率（`dpi / 96.0`），响应 `WM_DPICHANGED`：先把新 `dpiScale` 回传该窗 `Density`（同步更新 `dpScale` 与 `spScale`）触发重排测量，再应用系统 `lParam` 给出的建议物理窗口矩形。
  - `core` 与 `d3d11` 内部继续全用物理像素（PX）；`WindowState.size` 与 `minSize` / `maxSize` 的 `dp` 在窗口边界按该窗 `dpiScale` 换算为客户区物理像素。
- **IME 与文本输入（纯 Win32 IMM32，零 COM `ITextStoreACP`）**：
  - 只接 `imm32.lib`（`WM_IME_STARTCOMPOSITION`、`WM_IME_COMPOSITION`、`WM_IME_ENDCOMPOSITION`、`WM_IME_SETCONTEXT`、`ImmGetCompositionStringW`、`ImmSetCandidateWindow`、`ImmNotifyIME`、`ImmAssociateContext` / `ImmAssociateContextEx`），不引入 TSF COM 文本仓。
  - **按焦点开关输入法上下文**：当前窗焦点不在可编辑 `<Input>` 上（无焦点、聚焦普通节点、`<Input :enabled="false">` 或 `<Input :read-only="true">`）时 `ImmAssociateContext(hwnd, nullptr)`，防止按快捷键弹出输入法；聚焦可编辑 `<Input>` 时恢复默认 `HIMC`。
  - **清理 JUCE 时代遗留补丁**：删掉 `core::TextInputState` 与 `runtime::InputTextSession` 里的 `beginPlatformEdit`、`finishPlatformEdit`、`beginCompositionFromLastEdit`、`pendingPlatformEdit_`、`compositionCancelled_`；改为显式维护 `compositionRange` 与子句目标标记（区分 `ATTR_TARGET_CONVERTED` 粗/实下划线与普通未定段细下划线），提供直映 `WM_IME_*` 的 `setComposition`、`commitComposition`、`cancelComposition`。
  - **组合回执与主动打断**：组合进行中由原生叠层实时画出预编辑文本、段内光标与分段下划线，**不触发** JS `:on-value-change`；`GCS_RESULTSTR` 上屏时才触发 `:on-value-change` 并将整次组合合为单条 Undo（支持同一条消息先带 `GCS_RESULTSTR` 上屏前半句、紧接 `GCS_COMPSTR` 续写后半句）。鼠标点击移位、失焦、按 `Esc` 或外部 `value` 变更时调 `ImmNotifyIME(..., NI_COMPOSITIONSTR, CPS_CANCEL)` 收起系统候选框。
  - **`<Input>` 增强**：新增 `readOnly?: boolean`（默认 `false`：允许聚焦、选区、快捷键复制，禁止修改与开启 `HIMC`）；补齐 `Ctrl+Left/Right` 按词移动与选区、`Ctrl+Backspace/Delete` 按词删除、鼠标双击选词与三击选行、`WM_CHAR` UTF-16 代理对（Emoji）拼合与 `CF_UNICODETEXT` 剪贴板。
- **开发期诊断交互与剥离**：
  - Dev 宿主支持窗口级调试交互：`F5` 请求重载、`F8` 切换当前窗 FPS 徽标、`F9` 切换当前窗 `core::DiagnosticsOverlay`（`Shift+F9` 切换节点 `bounds` 描边与 `hit` 命中高亮）；错误屏下点击重试（`retryAvailable` 为真时）与 `Ctrl+C` 复制完整诊断文本到剪贴板。
  - Dist 宿主在编译/链接期物理剥离上述调试快捷键、`DiagnosticsOverlay`、`DiagnosticsHud` 与 HMR，`verify:host` 同步扩充剥离标记。

## 2. 应用入口、`createApp` 清算与多窗口协议桥

- [x] **TS 入口与原语**：实现 `appBuilder`、`<App>`（`&app-handle`）、`<Window>`（`&window-handle`）、`createWindowState`；彻底删除 `createApp` 与 `CantonApp`。

- [x] **HMR 兼容**：Live 热更新改 `<App>` 或 `<Window>` 子树时保持已有窗口 `HWND`、`WindowState`、焦点与响应式状态不闪烁重建；入口模块热重载或整体重载时干净回收旧会话窗口。
- [x] **跨语言多窗口协议**：扩充 `__CANTON_NATIVE__`、`ModifierNativeProtocol`（非客户区语义、`readOnly` 等，跑 `pnpm sync:modifier-protocol`）与 `QuickJsNativeApi` / `CantonRuntime`，使节点变更、绑定更新、事件槽、焦点命令、输入事件与窗口属性/几何/DPI 回执均按窗口身份精确路由。
- [x] **包分层守卫**：新增 TS 模块落入既定分层，`tests/runtime/package-layers.test.ts` 零循环导入通过。

## 3. 原生多窗口生命周期、Owner 与非阻塞模态

- [x] **多窗口管理器**：演进 `runtime` 与 `host`，从单窗固定创建改为由脚本事务驱动多窗口生灭；加上 `exitOnLastWindowClosed`（事务提交后判定，同帧切窗不误退）、`appHandle.exitApplication()`（不重入 `onCloseRequest`，按拓扑逆序关窗退出）以及 `WM_QUERYENDSESSION` / `WM_ENDSESSION` 有序卸载。
- [x] **关闭拦截**：拦截 `WM_CLOSE` 转交对应 `<Window>` 的 `onCloseRequest`（含 `windowState.requestClose()`），禁止 `DefWindowProc` 绕过组合树直接毁窗。
- [x] **Owner 继承与逆序销毁**：嵌套 `<Window>` 默认以最近祖先 `<Window>` 的 `HWND` 作为 Win32 `owner`（`owner="none"` 时不挂 `GWLP_HWNDPARENT`）；同一事务销毁父子窗时严格先销毁 Owned 子孙再销毁 Owner。
- [x] **非阻塞模态与防焦点跌落**：不用 `DialogBox`；按 `modality`（`'owner'` 锁该 `owner` 及其非模态 owned 子孙，无 `owner` 报错；`'application'` 锁本进程其余全部顶层窗）维护每窗模态锁计数与 `EnableWindow`。关闭模态窗时严格执行：**先减锁计数恢复目标窗 `EnableWindow(TRUE)` → `SetForegroundWindow`/`SetActiveWindow` 激活宿主目标窗 → 最后 `DestroyWindow` 模态窗**。
- [x] **0 窗错误屏兜底**：启动/Live 断连/早期异常尚无可见 `<Window>` 时自动开兜底窗展示错误屏，恢复后平滑移交真实应用窗。

## 4. 窗口外观、自绘标题栏、五级命中与 Per-Monitor DPI

- [x] **外观与能力**：实现 `chrome`（`system`、`customTitleBar`、`frameless`）、`role`（`standard`、`utility` 映射 `WS_EX_TOOLWINDOW`）、`resizable`/`minimizable`/`maximizable`/`closable`、`alwaysOnTop`、`visible`、`placement`（`normal`/`minimized`/`maximized`/`fullscreen` 含还原态记忆）、`position`、`minSize`/`maxSize`（`WM_GETMINMAXINFO`）及任务栏显隐联动。
- [x] **Win11 材质、圆角与任务栏身份**：对接 DWM `backdrop`（Mica / Mica Alt / Acrylic，此时窗口底色清为透明以透出材质；低版本或不支持环境静默回退常规深色底）与 `cornerPreference`；实现 `<App :app-id :icon>`（`SetCurrentProcessExplicitAppUserModelID` + 默认图标）与 `<Window :title :icon>`（WIC 解包内或 Live 图像转大小 `HICON`）。
- [x] **自绘标题栏与 5 级 `WM_NCHITTEST`**：`customTitleBar` 经 `WM_NCCALCSIZE` 去掉系统默认标题栏并在最大化时缩回系统外扩边框；按 ADR 004 严格落实 5 级命中（1. 四边四角缩放热区 → 2. `captionButton` 返回 `HTMINBUTTON`/`HTMAXBUTTON`/`HTCLOSE` 原生支持 Win11 Snap Layout 悬停浮层 → 3. 可交互节点与 `nonDraggableArea` 自动让位 `HTCLIENT` → 4. `draggableArea` 返回 `HTCAPTION` → 5. `HTCLIENT`）。
- [x] **非客户区三键托管防闪烁**：拦截三键上的 `WM_NCLBUTTONDOWN` / `WM_NCLBUTTONUP` / `WM_NCMOUSEMOVE` / `WM_NCMOUSELEAVE`，不交 `DefWindowProc` 画复古按钮，桥接进 Canton 指针与 `InteractionState` 驱动自绘三键的悬停/按压态，松开时按能力开关执行最小化、最大化/还原或发起关闭请求。
- [x] **Per-Monitor V2 DPI**：每窗初始化及收到 `WM_DPICHANGED` 时向脚本回传新 `dpiScale` 更新该窗 `Density`，应用系统建议窗口矩形，字形光栅化与交换链尺寸无缝跟进。

## 施工笔记

- **基线图核对说明**：全量迁移 `showcase` 等夹具至 `appBuilder(Root).build()` + `<App>` + `<Window>` 后，既有 24 张无头回归基线图在 WARP 档（最大通道差 0，超差像素 0）与硬件档（RTX 5070 Ti，全部在容差内）24/24 原样通过，**本次新增或修改的 PNG 基线图数量为 0**。`RenderCasesFixture.cpp` 同步扩充了 `MultiWindowFixtureSession`，支持按窗口序号或窗口标题对多窗口夹具的指定窗口做离屏取图。
- **Win11（Build 26300，2560×1440 @ 150% DPI / 144 DPI）真窗实测与踩坑修复**：
  1. **Per-Monitor V2 DPI 与 `WM_NCCALCSIZE` 双态处理**：预构建宿主尚无 M8 注入的 PE DPI 清单，需在进程入口及窗口查询前显式调用 `SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)`；同时 `CreateWindowExW` 初建窗口会先发送 `wParam == FALSE` 的 `WM_NCCALCSIZE`，若只拦截 `wParam == TRUE` 会导致初次建窗被 `DefWindowProcW` 扣掉 `(15px, 38px)` 系统边框并造成非客户区命中偏移。统一拦截 `wParam == FALSE/TRUE` 并在建窗后触发 `SWP_FRAMECHANGED` 后，`980.dp × 640.dp` 工作台在 `144 DPI` 显示器上精确测得物理客户区 `1470 × 960 px`。
  2. **最大化不裁边、消除 DWM 幽灵系统三键与五级 `WM_NCHITTEST` / Snap Layout**：`customTitleBar` 与 `frameless` 样式显式剥离 `WS_SYSMENU`（同时在 `customTitleBar` 保留 `WS_CAPTION | WS_THICKFRAME | WS_MAXIMIZEBOX | WS_MINIMIZEBOX`），彻底消除 Win11 `uDWM.dll` 在 Mica/Acrylic 半透明材质底层叠画的不可点击系统三键残影；`IsZoomed(hwnd)` 时在 `WM_NCCALCSIZE(TRUE)` 按 `GetSystemMetricsForDpi(SM_CXSIZEFRAME/SM_CYSIZEFRAME + SM_CXPADDEDBORDER)` 内缩并夹紧到显示器 `rcWork`，实测最大化客户区 `2560 × 1392 px` 与 `rcWork` 完全吻合、零裁边。实窗 `SendMessage(WM_NCHITTEST)` 验证五级优先级全部命中：顶边缩放带 `HTTOP(12)`、自绘三键 `HTMINBUTTON(8)` / `HTMAXBUTTON(9)` / `HTCLOSE(20)`、标题栏内嵌搜索 `<Input>` 自动让位 `HTCLIENT(1)`、标题栏空白拖拽区 `HTCAPTION(2)`。三键 `WM_NCLBUTTONDOWN` 不调用 `SetCapture`；客户区 `WM_LBUTTONUP` 先派发 `pointerUp` 再在 `releasingCapture` 保护下调 `ReleaseCapture()`，防止同步重入的 `WM_CAPTURECHANGED` 误取消点击。
  3. **DWM Mica 材质与诊断浮层 DPI 缩放**：实测 `DwmGetWindowAttribute(hwnd, 38)` 返回 `2`（`DWMSBT_MAINWINDOW`），启用成功时渲染器将窗口底色清为 `0x00000000` 透出系统 Mica 材质；不支持环境自动回退 `0xff1f232a` 深色底。`DiagnosticsScene`（`LIVE` 角标、FPS 徽标、Toast 气泡）、`ErrorScreenModel` 与 `DiagnosticsOverlay` 全量按所属窗口 `dpiScale` 缩放，并在 `customTitleBar` 下自动下移避让顶部自绘三键。
  4. **关闭拦截、嵌套模态、`exitApplication` 有序退出与防焦点跌落**：`AppSession` 对 `controlRuntime_` 开启 `externalSurfaceHost` 隔离，禁止单视口事件派发吞取多窗口变更与退出请求；`onRequestExit` 通知消息循环退出并在退泵后执行 `shutdownSession()`。向主工作台发送 `WM_CLOSE` 经 `onCloseRequest` 弹出模态确认窗并实测 `IsWindowEnabled(mainHwnd) == FALSE`，点击确认退出按钮有序销毁全部窗口并以退出码 `0` 结束进程；二级嵌套模态按锁计数叠加，关闭内层模态时严格按“减锁恢复目标窗 `EnableWindow(TRUE)` → `SetForegroundWindow`/`SetActiveWindow` → `DestroyWindow`”执行。
  5. **Live 入口 TLA 与空闲唤醒**：Live 快照引导模块 `/@canton/entry` 通过命名空间导入执行 `globalThis.__CANTON_LAUNCH_APP__`，既兼容含顶层 `await` 的模块求值顺序，又保证导出应用定义自动启动；宿主 `MessageDispatcher` 在 VBlank 停表空闲期收到后台 Live/资源线程唤醒时直接推进单拍帧检查点，跑通 `lfd` 断连回退 Dist 与重连切回 Live 全流程。
  6. **纯 IMM32 组合输入与 DirectManipulation 坐标对齐**：`WindowsPrecisionWheelSource` 以 `scale = 1.0f` 对齐 `core` 物理像素坐标系；IMM32 在 `WM_IME_SETCONTEXT` 剥离 `ISC_SHOWUICOMPOSITIONWINDOW`，通过 `CFS_EXCLUDE` 将系统候选框定位到行内光标矩形下方，支持单条 `WM_IME_COMPOSITION` 同时携带 `GCS_RESULTSTR` 上屏与 `GCS_COMPSTR` 续写，并在 Lazy 列表前插/反转重排期间完整保留焦点、选区与活跃 `compositionRange`。
