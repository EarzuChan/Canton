## 0. 已定口径

- **内建件迁移范围**：五个布局件加 Lazy 四件套和 Crossfade，比 ROADMAP 原写的范围多，退出时同步 ROADMAP。
- **`&param="..."` 的值**：单个标识符别名，或解构模式。
- **验证方式**：TS 与 C++ 分段验证，不在本期新建走 QuickJS 的布局夹具用例。
- **父级校验口径（草案建议，待主人确认）**：保持 C++ 现有规则，按父布局数据的种类校验，不给 ParentData 加来源布局种类或容器实例身份。
  - 现有规则：`matchParentSize` 只认 Box；`weight` 认 Row、Column、Flow；`align` 按实际父级的交叉轴方向核对。违反即报错。
  - Compose 的做法（核对自 `foundation-layout` 1.11.1 源码）：`RowScope`、`ColumnScope`、`BoxScope` 都是无状态单例；Row 和 Column 的 `weight` 是同一个元素，写进同一份 `RowColumnParentData`；父布局用 `parentData as? X` 读取，种类不符就静默忽略，运行期没有任何校验，只靠 `@LayoutScopeMarker` 在编译期拦。
  - 所以现有规则的划分与 Compose 的父数据种类一致，并且把 Compose 静默忽略的情形改成了报错，已满足 ADR 002 举的“Column 的 `weight` 装到 Box 子项应报错”。
  - 剩下不报错的两种情形：`weight` 在 Row、Column、Flow 之间互传（语义相同，都是按主轴分配）；外层容器的 Handle 用在内层同种容器的子项上。要拦它们得让每份父布局数据带上来源，收益小。
  - 本期新增的几项沿用同一口径：`alignBy` 认 Row 和 FlowRow，`fillMaxRowHeight` 只认 FlowRow，`fillMaxColumnWidth` 只认 FlowColumn，`fillParentMax*` 只认 LazyColumn 和 LazyRow 的项。
- **能力补齐的取舍**：Compose 的 Scope 上有、Canton 原生还没有的能力，凡是只涉及测量、能用 C++ core 用例验住的，本期一并补齐；涉及动画和绘制的、需要测量中途回调脚本的，移交后续里程碑（见文末）。

## 1. 内建件梳理

| 内建件 | 现状 | M2 处理 |
| --- | --- | --- |
| Box | 默认槽无参 | 默认槽交付 `boxHandle`：`align`、`matchParentSize` |
| Row | 默认槽无参 | 默认槽交付 `rowHandle`：`weight`、`align`（垂直对齐）、`alignBy`（对齐线）、`alignByBaseline` |
| Column | 默认槽无参 | 默认槽交付 `columnHandle`：`weight`、`align`（水平对齐） |
| FlowRow | 默认槽无参 | 默认槽交付 `flowRowHandle`：`weight`、`align`（垂直对齐）、`alignBy`、`alignByBaseline`、`fillMaxRowHeight` |
| FlowColumn | 默认槽无参 | 默认槽交付 `flowColumnHandle`：`weight`、`align`（水平对齐）、`fillMaxColumnWidth` |
| LazyColumn、LazyRow | 用 `itemContent` + `itemProps` 传定义 | 删掉这两个参数，默认槽交付 `item`、`index` 和 `lazyItemHandle`：`fillParentMaxSize`、`fillParentMaxWidth`、`fillParentMaxHeight` |
| LazyVerticalGrid、LazyHorizontalGrid | 同上 | 删掉这两个参数，默认槽交付 `item`、`index`；Compose 的网格项 Scope 只有 `animateItem`，本期不交付 Handle |
| Crossfade | 用 `is` + `props` 传定义 | 删掉这两个参数，默认槽交付 `state`（该层对应的 `targetState` 值） |
| DynamicArrangable | 把收到的内容原样转给 `is` | 保留；带参内容原样透传，参数类型按 `is` 推导 |
| Layout、KeepAlive、AnimatedVisibility | 默认槽无参 | 不加参数；AnimatedVisibility 内部那层 Box 的 Handle 不外露 |
| Spacer、Text、Input、Image、Icon、Canvas | 无槽 | 不涉及 |

- [ ] 主人过目上表，参数名（`boxHandle`、`lazyItemHandle`、`item`、`index`、`state` 等）定稿后再动代码。

本期不做：

- Lazy 项的 `animateItem`、回调形式的 `alignBy`，去向见文末“移交后续里程碑”。
- Column 的 `alignBy`：Canton 没有垂直对齐线的来源。
- `appHandle`、`windowHandle`（M4）与 `menuHandle`（M6）。本期只交付它们依赖的槽位传参机制。

## 2. 编译器：模板语法

- [ ] **`&` 绑定的词法与解析**：属性位置的 `&name` 和 `&name="..."` 解析为槽位参数绑定，参数名按现有规则归一化（`&app-handle` 对应 `appHandle`）。`&` 后面到 `=` 或空白为止整段就是参数名，没有修饰符和动态参数名这两种形式。
- [ ] **绑定值**：省略时以参数名为局部名；写标识符时作为别名；写解构模式时用 Babel 解析出全部局部名，支持对象与数组模式、重命名、默认值、嵌套和 rest。
- [ ] **绑定位置**：默认槽的绑定写在 Arrangable 标签上，具名槽的绑定写在 `<Template #name>` 上；写在 `<Slot>`、不带 `#` 的 `<Template>` 或其它位置时报错。
- [ ] **作用域**：
  - 局部名只在对应的内容模板里可见，标签自身的参数和指令（含同标签上的 `c-if`、`c-for`）看不到它。
  - 局部名遮蔽外层同名绑定，包括 `<script>` 里的绑定和外层槽位参数；嵌套同一容器时，外层起别名、内层用原名可以同时访问两者。
  - 提供方交付了但使用方没有用 `&` 接的参数不占名字，同名标识符继续按普通规则向外查找。
- [ ] **重复检查**：同一处重复绑定同一参数、两个绑定产生同一局部名时报错。
- [ ] **`<Slot>` 出口传参**：除静态 `name` 外接受 `:param="表达式"` 和静态 `param="文本"`，参数名同样归一化；`name` 和 `key` 是保留名；仍不接受 `c-bind` 展开、动态参数名和子内容。
- [ ] **槽位名只认 `#name`**：编译器里没有针对 `c-slot:*` 的专门判断，它和任何不认识的 `c-*` 一样走通用的未知指令处理，本期也不新增；删掉专门锚定这个写法的用例“CTA 拒绝长写槽位指令”。
- [ ] **代码生成**：内容函数接收参数；出口把实参交给内容；内容里引用了槽位参数时，不再把内容表提升到 setup。
- [ ] **顺手修正**：模板契约检查的两条报错文案还写着 `a-` 前缀，改成 `c-`。
- [ ] **SourceMap**：`&` 绑定、出口实参和内容里对参数的引用都能映射回 `.cta` 原位置。

## 3. 编译器：`defineSlots` 与类型检查

- [ ] **`defineSlots<...>()` 宏**：只接受类型实参，一个文件最多调用一次，只能写在 `<script>` 顶层语句位置，不产生运行期代码；和 `defineProps` 一样无需导入，也不能读实例局部变量。
- [ ] **声明与出口合并**：模板里出现的 `<Slot>` 决定有哪些槽位，`defineSlots` 里没写的槽位视为零参数。
- [ ] **定义类型携带槽位签名**：`.cta` 产出的定义和 TS 手写的定义都能让使用方推导出各槽位的参数类型。
- [ ] **使用方检查**：`&` 的局部名（含别名和解构出的各个名字）按槽位签名得到类型；绑定了未声明的参数时报错；继续拒绝未声明的具名槽。
- [ ] **提供方检查**：出口传了未声明的参数、缺少必需参数、实参类型不符、`defineSlots` 声明的槽位在模板里没有出口，各报一条诊断。
- [ ] **随参数变化的签名**：Lazy 的 `item` 类型取自 `items` 的元素类型，Crossfade 的 `state` 类型取自 `targetState`，DynamicArrangable 的槽位签名取自 `is`。
- [ ] **诊断定位**：报在对应的 `&` 绑定或 `<Slot>` 实参上，不笼统报在标签起点。
- [ ] `typecheck:cta` 覆盖新增夹具。

## 4. 运行时：带参内容

- [ ] **内容契约**：内容函数从无参改为接收一个参数对象；`SetupContext` 的 `slots`、`slot()` 和 `useSlots()` 的类型同步；“内容必须是无参数结构函数”的校验相应放开。
- [ ] **定义侧声明**：TS 手写的 `defineArrangable` 能声明各槽位的参数，供运行期校验和类型推导；定义允许的字段、参数计划（`prepareParameters`）和 HMR 契约摘要一并更新。
- [ ] **出口调用**：同一个槽位可以有多个出口，每个出口传各自的实参，各次执行有独立的内容作用域和调用身份。
- [ ] **实参更新**：
  - 实参变化只影响对应出口；存续的子实例按现有 position 和 key 规则匹配，不重建。
  - 参数按读取位置追踪：只在值位置读到的参数走值绑定更新，不重跑内容；在结构位置（`c-if`、`c-for`、`key`）读到的才重跑内容作用域。别名和解构出的名字同样如此。
  - 稳定对象上通过 getter 读取的响应式字段，由实际读取位置追踪。
- [ ] **转交**：一个 Arrangable 把收到的内容交给内部子件时可以补上自己的参数（Box 把内容交给 Layout 时补 `boxHandle`），也可以原样透传（DynamicArrangable）。
- [ ] **开发期诊断**：使用方绑定了出口没有传的参数时报错并带来源位置。
- [ ] 新增和移动的文件放进已登记的层，`package-layers` 用例通过。

## 5. 布局 Handle

- [ ] **内部构造入口**：父布局数据只能经 Handle 构造，公开的 `Modifier` 类和 `M` 上没有这些方法；确认已有的 `weight`、`align`、`matchParentSize` 经 Modifier 降级和原生协议表准入仍然走通。
- [ ] **Handle 的方法**见第 1 节的表。`weight` 接收权重和 `fill` 选项，权重不大于零时抛错；`align` 的参数类型按该布局的交叉轴限定，传错方向时 TS 报错；各 `fill*` 方法接收 0 到 1 的比例，默认 1，越界抛错。
- [ ] **按对齐线对齐**（Row、FlowRow）：
  - `alignBy(对齐线)` 接受 `FirstBaseline`、`LastBaseline`，`alignByBaseline()` 等同于按首行基线。
  - 原生把 Row 现有的 Baseline 对齐推广为按指定对齐线对齐；FlowRow 在每一行内各自对齐；文本布局服务除首行基线外给出末行基线。
  - `rowHandle.align` 只收垂直对齐，不再收 `Baseline`；Row 自身的 `verticalAlignment="Baseline"` 参数不变。
- [ ] **Flow 交叉轴填充**：`fillMaxRowHeight` / `fillMaxColumnWidth` 让子项按比例占满所在行（列）里最高（最宽）一项的尺寸；行（列）的尺寸先由不带该项的子项定出，再回测带该项的子项；固有尺寸查询同步处理；一行全是填充项时的规则对照 Compose 定。
- [ ] **Lazy 项按视口填充**：`fillParentMaxSize` / `fillParentMaxWidth` / `fillParentMaxHeight` 按所在 Lazy 容器的视口尺寸（扣除 `contentPadding`）乘以比例定约束；用在 Lazy 项之外时报错。
- [ ] **协议表**：新增的父布局数据写进 Modifier 原生协议表，`sync:modifier-protocol` 重新生成 C++ 表，C++ 的父布局数据结构和校验相应扩充。
- [ ] **返回普通 Modifier 片段**：由调用方用 `then()` 插入链中，链上的顺序原样保留。
- [ ] **Handle 是无状态的冻结对象**：同种布局共用一个，实参恒定，不会引起内容重跑。
- [ ] **五个布局件经默认槽交付各自的 Handle**（`lazyItemHandle` 的交付见第 6 节）。
- [ ] **校验口径**按第 0 节执行；主人若改选更严的口径，在这里追加协议表和 C++ 的改动项。
- [ ] 原生报错文案里提到 `Modifier.align` 这类旧入口的，改成按 Handle 的说法。

## 6. Lazy 与 Crossfade 改用槽位传参

- [ ] **Lazy 四件套**：删除 `itemContent`、`itemProps`；每个可见项执行一次默认槽，交付 `item` 和 `index`，LazyColumn 和 LazyRow 另交付 `lazyItemHandle`；项的身份仍取自 `itemKey`，离屏逻辑项的保留上限、活动范围随数据重排迁移等现有行为不变。
- [ ] **Crossfade**：删除 `is`、`props`；每一层执行一次默认槽，交付该层的 `state`；退出中的层保留切换前的值，切回旧状态时不重复创建逻辑实例。
- [ ] 迁移 `tests/fixtures/m3-lazy`（`LazyApp.cta` 及两个项文件）、`m3-lazy.test.ts`、`m3-lazy-state.test.ts` 与 `value-binding.test.ts` 里的 Crossfade 用例，断言内容不减。

## 7. HMR

- [ ] **契约判定**：槽位签名（槽位名和各槽位的参数）计入契约，签名变化按不兼容处理，与 props 变化同一规则。
- [ ] **模板热更新**：使用方增删 `&` 绑定、改别名，提供方增删出口或改实参，都保留 `ref` 状态和原生节点；模板工厂不把槽位参数的局部名当成 setup 变量改写。
- [ ] **父子分别热更新**：子件兼容更新后，父级沿用的参数计划和带参内容仍可调用。
