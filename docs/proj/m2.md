## 0. 已定口径

- **内建件迁移范围**：五个布局件加 Lazy 四件套和 Crossfade，比 ROADMAP 原写的范围多，退出时同步 ROADMAP。
- **`&param="..."` 的值**：单个标识符别名，或解构模式。
- **验证方式**：TS 与 C++ 分段验证，不在本期新建走 QuickJS 的布局夹具用例。
- **父级校验口径**：保持 C++ 现有规则，按父布局数据的种类校验，不给 ParentData 加来源布局种类或容器实例身份。
  - 现有规则：`matchParentSize` 只认 Box；`weight` 认 Row、Column、Flow；`align` 按实际父级的交叉轴方向核对。违反即报错。
  - Compose 的做法（核对自 `foundation-layout` 1.11.1 源码）：`RowScope`、`ColumnScope`、`BoxScope` 都是无状态单例；Row 和 Column 的 `weight` 是同一个元素，写进同一份 `RowColumnParentData`；父布局用 `parentData as? X` 读取，种类不符就静默忽略，运行期没有任何校验，只靠 `@LayoutScopeMarker` 在编译期拦。
  - 所以现有规则的划分与 Compose 的父数据种类一致，并且把 Compose 静默忽略的情形改成了报错，已满足 ADR 002 举的“Column 的 `weight` 装到 Box 子项应报错”。
  - 剩下不报错的两种情形：`weight` 在 Row、Column、Flow 之间互传（语义相同，都是按主轴分配）；外层容器的 Handle 用在内层同种容器的子项上。要拦它们得让每份父布局数据带上来源，收益小。
  - 本期新增的几项沿用同一口径：`alignBy` 认 Row 和 FlowRow；`fillMaxRowHeight` 与 `fillMaxColumnWidth` 是同一种数据（Compose 里也是同一个元素），认 Flow；`fillParentMax*` 是按最近的 Lazy 容器求值的布局项，用在 Lazy 项之外报错。
- **能力补齐的取舍**：Compose 的 Scope 上有、Canton 原生还没有的能力，凡是只涉及测量、能用 C++ core 用例验住的，本期一并补齐；涉及动画和绘制的、需要测量中途回调脚本的，移交后续里程碑（见文末）。

## 1. 内建件梳理

| 内建件 | 现状 | M2 处理 |
| --- | --- | --- |
| Box | 默认槽无参 | 默认槽交付 `boxHandle`：`align`、`matchParentSize` |
| Row | 默认槽无参 | 默认槽交付 `rowHandle`：`weight`、`align`（垂直对齐）、`alignBy`（对齐线）、`alignByBaseline` |
| Column | 默认槽无参 | 默认槽交付 `columnHandle`：`weight`、`align`（水平对齐） |
| FlowRow | 默认槽无参 | 默认槽交付 `flowRowHandle`：`weight`、`align`（垂直对齐）、`alignBy`、`alignByBaseline`、`fillMaxRowHeight` |
| FlowColumn | 默认槽无参 | 默认槽交付 `flowColumnHandle`：`weight`、`align`（水平对齐）、`fillMaxColumnWidth` |
| LazyColumn、LazyRow | 用 `itemContent` + `itemProps` 传定义 | 删掉这两个参数，默认槽交付 `item`、`index` 和 `lazyItemHandle`：`fillParentMaxSize`、`fillParentMaxWidth`、`fillParentMaxHeight` |
| LazyVerticalGrid、LazyHorizontalGrid | 同上 | 删掉这两个参数，默认槽交付 `item`、`index`；Compose 的网格项 Scope 只有 `animateItem`，本期不交付 Handle |
| Crossfade | 用 `is` + `props` 传定义 | 删掉这两个参数，默认槽交付 `state`（该层对应的 `targetState` 值） |
| DynamicArrangable | 把收到的内容原样转给 `is` | 保留；带参内容原样透传，参数类型按 `is` 推导 |
| Layout、KeepAlive、AnimatedVisibility | 默认槽无参 | 不加参数；AnimatedVisibility 内部那层 Box 的 Handle 不外露 |
| Spacer、Text、Input、Image、Icon、Canvas | 无槽 | 不涉及 |

- [x] 主人过目上表，参数名（`boxHandle`、`lazyItemHandle`、`item`、`index`、`state` 等）定稿后再动代码。

本期不做：

- Lazy 项的 `animateItem`、回调形式的 `alignBy`，去向见文末“移交后续里程碑”。
- Column 的 `alignBy`：Canton 没有垂直对齐线的来源。
- `appHandle`、`windowHandle`（M4）与 `menuHandle`（M6）。本期只交付它们依赖的槽位传参机制。

## 2. 编译器：模板语法

- [x] **`&` 绑定的解析**：以 `&` 开头的属性是槽位参数绑定，`&` 后面到 `=` 或空白为止整段就是参数名，按现有规则归一化（`&app-handle` 对应 `appHandle`）。没有修饰符和动态参数名这两种形式。
- [x] **绑定值**：省略时以参数名为局部名；写标识符时作为别名；写解构模式时按形参解析，对象与数组模式、重命名、默认值、嵌套和 rest 都是 JS 自身的解构，默认值表达式照常引用外层绑定。
- [x] **绑定位置**：默认槽的绑定写在 Arrangable 标签上，具名槽的绑定写在 `<Template #name>` 上；写在 `<Slot>` 或不带 `#` 的 `<Template>` 上时报错。标签没有默认内容时不生成内容函数，上面的绑定随之略去。
- [x] **作用域**：`&` 绑定降为内容函数的形参解构，所以局部名只在对应内容里可见、遮蔽外层同名绑定；嵌套同一容器时外层起别名、内层用原名可以同时访问两者；没有用 `&` 接的参数不占名字，同名标识符继续向外查找。
- [x] **重复检查**：同一处重复绑定同一参数、两个绑定产生同一局部名、参数名不是合法标识符时报错。
- [x] **`<Slot>` 出口传参**：除静态 `name` 与 `key` 外，`:param="表达式"` 和静态 `param="文本"` 都是交付给内容的实参；不接受 `c-bind` 展开、动态参数名和子内容。
- [x] **槽位名只认 `#name`**：编译器里没有针对 `c-slot:*` 的专门判断，它和任何不认识的 `c-*` 一样走通用的未知指令处理；专门锚定这个写法的用例“CTA 拒绝长写槽位指令”已删。
- [x] **代码生成**：
  - 带实参的出口生成 `() => 内容(实参)`，实参在该出口的内容作用域里求值；不引用模板局部名时这个函数只在 setup 里建一次。
  - 一次调用的内容表用 `satisfies` 按“定义 + 本次调用的参数”约束，`&` 的局部名由此得到类型。约束只存在于类型，转译时擦除，类型检查与值单位分析共用同一份产物。
- [x] **顺手修正**：模板契约检查的两条报错文案从 `a-` 前缀改成 `c-`。
- [x] **SourceMap**：每个 `&` 绑定、每个槽位内容、每个出口及其实参都有映射点。

## 3. 编译器：`defineSlots` 与类型检查

- [x] **`defineSlots<...>()` 宏**：写在 `<script>` 顶层语句位置，类型实参声明各槽位交付的参数；一个文件最多调用一次；不产生运行期代码，没有返回值（写在变量初始化里时报错），无需导入。
- [x] **声明与出口合并**：模板里出现的 `<Slot>` 决定有哪些槽位，`defineSlots` 里没写的槽位没有参数；只写在 `defineSlots` 里、模板没有出口的名字不算槽位。
- [x] **定义类型携带槽位参数**：`.cta` 产出的定义和 TS 手写的定义都带槽位声明；参数类型随调用参数变化的定义另挂一个只存在于类型的 `slotTypes`。
- [x] **使用方检查**：`&` 的局部名（含别名和解构出的各个名字）按槽位参数得到类型；绑定了未声明的参数、使用了未声明的具名槽时报错。
- [x] **提供方检查**：出口传了未声明的参数、缺少必需参数、实参类型不符时报错。
- [x] **随参数变化的类型**：Lazy 的 `item` 取自 `items` 的元素类型，Crossfade 的 `state` 取自 `targetState`，DynamicArrangable 的各槽位取自 `is`。
- [x] **诊断定位**：使用方的错误落在对应的 `&` 绑定或 `<Template #name>` 上，提供方的错误落在 `<Slot>` 或对应实参上。
- [x] `typecheck:cta` 覆盖迁移后的夹具（含 Lazy 的 `&item`）。

## 4. 运行时：带参内容

- [x] **内容契约**：内容函数按值接收一个参数对象，出口没有交付参数时收到空对象；`SetupContext` 的 `slots`、`slot()` 和 `useSlots()` 按槽位声明给出类型。
- [x] **定义侧声明**：`defineArrangable` 的 `slotNames` 换成 `slots: { 名称: slotParams<参数>() }`，运行期只用到槽位名，参数只在类型层面。
- [x] **出口调用**：一个出口对应一个内容作用域和调用身份；同一个槽位可以有多个出口，各传各的实参。
- [x] **实参更新**（按 ADR 002：实参是该出口的结构输入）：实参在出口自己的内容作用域里求值，变化只重跑这个出口的内容，不连带父级和其它出口；存续的子实例按现有 position 和 key 规则匹配，参数经值绑定刷新，不重建；稳定对象上通过 getter 读取的响应式字段仍由实际读取位置追踪。
- [x] **转交**：把收到的内容交给内部子件时可以补上自己的参数（Box 补 `boxHandle`），可以原样透传（DynamicArrangable），也可以不外露内部件的参数（AnimatedVisibility）。
- [x] 新增文件放进已登记的层，`package-layers` 用例通过。

没有做运行期的“绑定了出口没传的参数”诊断：这类错误由类型检查报出，运行期按 JS 解构的规则得到 `undefined`。

## 5. 布局 Handle

- [x] **Handle 只是 Modifier 片段的构造入口**：各 Handle 集中在 framework 的 `modifier/layoutHandle.ts`，方法返回普通 Modifier 片段，由调用方用 `then()` 插入链中或直接接着往下链；公开的 `Modifier` 类和 `M` 上没有这些方法。
- [x] **Handle 的方法**见第 1 节的表。`weight` 接收权重和 `fill` 选项，权重不大于零时抛错；`align` 的参数类型按该布局的交叉轴限定；各 `fill*` 方法接收 0 到 1 的比例，默认 1，越界抛错。
- [x] **Handle 是无状态的冻结对象**：同种布局共用一个，实参恒定，不会引起内容重跑。五个布局件经默认槽交付各自的 Handle。
- [x] **按对齐线对齐**（Row、FlowRow）：
  - `alignBy(对齐线)` 接受 `AlignmentLine.FirstBaseline`、`AlignmentLine.LastBaseline`，`alignByBaseline()` 等同于按首行基线。
  - 原生：按线对齐的兄弟项共用一条线，各自的线可以不同（一项的末行基线可以对另一项的首行基线）；Row 的 `verticalAlignment="Baseline"` 是同一机制的默认值；FlowRow 在每一行内各自对齐；节点与文本布局结果都带首行、末行两条基线。
  - `rowHandle.align` 只收垂直对齐；Row 自身的 `verticalAlignment="Baseline"` 参数不变。
- [x] **Flow 交叉轴填充**：`fillMaxRowHeight` / `fillMaxColumnWidth` 让子项按比例占所在行（列）的交叉轴尺寸。这个尺寸取行内已测量项的实测值与待定项（权重项、填充项）固有尺寸的最大值，与 Compose 一致；所以整行都是填充项时各项取自身固有尺寸，Flow 的固有尺寸查询结果也不受填充影响。
- [x] **Lazy 项按视口填充**：`fillParentMaxSize` / `fillParentMaxWidth` / `fillParentMaxHeight` 按最近的 Lazy 容器的视口（扣除 `contentPadding`）乘以比例定出强制尺寸；视口变化时只让读过它的节点及其上层重新测量；用在 Lazy 项之外时报错。
- [x] **协议表**：新增 `alignBy`、`fillCrossAxis`、`fillParentMaxWidth` / `Height` / `Size` 五项，C++ 生成表已同步，QuickJS 读取、core 的数据结构与校验相应扩充。
- [x] **校验口径**按第 0 节执行。
- [x] 原生报错文案不再提 `Modifier.align` 这类旧入口。
- [x] **比例越界**：原生对 `fillMax*`、`fillParentMax*` 和交叉轴填充的越界比例一律报错，不再静默夹取；与 TS 侧抛错一致。

## 6. Lazy 与 Crossfade 改用槽位传参

- [x] **Lazy 四件套**：删除 `itemContent`、`itemProps`；每个可见项执行一次默认槽，交付 `item` 和 `index`，LazyColumn 和 LazyRow 另交付 `lazyItemHandle`；`item` 与 `index` 在该项自己的内容作用域里读取，数据变化只重跑这一项；项的身份、离屏逻辑项的保留上限、活动范围随数据重排迁移等行为不变。
- [x] **Crossfade**：删除 `is`、`props`；每一层执行一次默认槽，交付该层建立时的 `state`；退出中的层不随目标状态改变，切回旧状态时沿用原来那层。
- [x] 迁移 `tests/fixtures/m3-lazy/LazyApp.cta`、`m3-lazy.test.ts`、`m3-lazy-state.test.ts` 与 `value-binding.test.ts` 里的 Crossfade 用例，断言内容不减。
