# M1 任务清单：品牌更名、Native 统一与大清场

承接 [ROADMAP.md](ROADMAP.md#m1品牌更名native-统一与大清场) 与 [ADR 009](../adr/batch1/9：宿主加载规矩、Native统一结构与扩展交付.md)。

> **本期原则**：**代码干净优先于强行可编可跑**。属于后续里程碑的缺口（Win32/D3D11、WIC 图像解码、WinSock/WinHTTP Live 客户端、ZIP `UiPackage`、新 CLI 业务链路）直接清干净并留白，**绝不造过渡假桩**；仅保持原本就完全独立的纯逻辑层（`packages/` TS 侧、`native/src/core/`、`native/src/quickjs/`）、非缺口区的编译/类型检查不红，作为更名防手滑的安全网。

---

## 1. 仓级配置、品牌更名与版本归零

- [x] 清理根目录 `package.json` 中的非标准注释，根包名与脚本命令统一改为 `canton`。
- [x] `arrange.version.json` 迁为 `canton.version.json`，版本与协议号归零重启：`frameworkVersion: "0.1.0"`、`cliVersion: "0.1.0"`、`frameworkInternalProtocolCode: 1`、`cliCompatibility: 1`。
- [x] `packages/*` 全部更名为 `@canton/{shared,reactivity,compiler,framework,vite-plugin}`，`cli/` 更名为 `@canton/cli`；同步 `scripts/version-contract.ts`、`scripts/build-internal-packages.ts`、`scripts/pack-npm-package.ts` 等脚本契约。
- [x] 全局标识符与类型声明收口：`types/arrange-globals.d.ts` → `types/canton-globals.d.ts`、`globalThis.__ARRANGE_NATIVE__` → `__CANTON_NATIVE__`、`__ARRANGE_HOT_*` → `__CANTON_HOT_*`、`ARRANGE_*` → `CANTON_*`、`.arrange/` → `.canton/`、`Arrange*` → `Canton*`（保留 `Arrangable` 与 `Rearrange`）。
- [x] 清理 `scripts/` 中对已删除 `demo/ui-src` 的残留引用。

## 2. DSL、字节码与 UI 包后缀迁移

- [x] 编译器（`packages/compiler`）与 Vite 插件（`packages/vite-plugin`）：
  - 单文件后缀由 `.sfa` 统一改为 **`.cta`**（含解析、缓存、HMR、SourceMap、离线类型检查 `checkCtaProject`）。
  - 模板指令前缀由 `a-*` 改为 **`c-*`**（`c-if`、`c-else-if`、`c-else`、`c-for`、`c-bind`；同步清理 `a-slot:*`）。
  - Dev 虚拟路径与协议标识切换为 `/@canton/modules`、`/@canton/entry`、`canton:import*`。
- [x] UI 包与字节码标识：
  - 清单文件名由 `arrange-ui.json` 改为 **`canton-ui.json`**，字节码模块后缀由 `.aex` 改为 **`.cbc`**，协议版本对齐 `1`。
  - 同步更新 `tests/fixtures/**` 中所有 `.sfa` 示例文件与 `tests/runtime/**` 引用。

## 3. 旧修饰器打掉与音频残留清理

- [x] **全链路连根清除旧 CPU 模糊（ADR 006）**：
  - 删除 `M.blur` / `M.backdropBlur` 及 Modifier 原生协议表（当时名为 `modifierSchema`）中的对应项，并重新生成 C++ 侧生成表。
  - 删除 C++ `EffectKind::Blur` / `EffectKind::BackdropBlur` 及 `Repaint` 中对应的旧 CPU 模糊扩散分支与旧测试用例（`draw.test.ts`、`m3_draw.cpp`、`repaint_region.cpp`）。
- [x] **先行打掉公开父布局特权 Modifier（为 ADR 002 铺路）**：
  - 从公开 `Modifier` 类与编译器 `codegen.ts` 快捷链列表中移除 `M.align()`、`M.weight()`、`M.matchParentSize()`。
  - **保留**底层 `ParentData` 协议字段、C++ `ParentDataModifierSemantics` 与 `LayoutTree`/`MeasurePolicy` 布局实现（供 M2 布局 Handle 直接复用）。
  - 清理受影响的 2 处测试夹具（`tests/fixtures/lazy/LazyApp.cta`、`tests/fixtures/layout/LayoutApp.cta`）中对旧公开方法的调用，更新 `tests/runtime/public-api.test-d.ts` 断言旧入口已移除。
- [x] **清除音频插件残留**：
  - 清理原生协议（现 `packages/framework/src/native/protocol.ts`）中的 `NativeHostFormat`、`NativeHostInfo`、`NativeTransport`、`NativeInterop*` 与 `packages/framework/package.json` 死导出 `./interop`。
  - 泛化 `packages/framework/src/draw/dataSource.ts` 的 `DataSourceKind`（去掉写死的 `'meter' | 'waveform' | 'spectrum'`）。
  - 清除 C++ 侧残留的 `Interop.h`、`QuickJsInterop` 引用。

## 4. Native 统一结构、去 JUCE 化与拆单例

- [x] **统一目录与 CMake 结构**：
  - 撤销 `native/arrange_core`、`native/arrange_quickjs`、`native/arrange_juce` 三工程拆分，整合为单一 `native/`：
    - `native/CMakeLists.txt`
    - `native/include/canton/`（预留给后续 `canton-sdk` 公开头文件）
    - `native/src/core/`（保持零 Win32 / D3D11 依赖）
    - `native/src/quickjs/`（含 `canton_ui_bytecode` 工具与 `ModifierNativeProtocol.inc`）
    - `native/src/runtime/`（收纳原 `arrange_juce` 中可复用的宿主编排资产）
    - `native/src/win32/`（先收纳 `WindowsPrecisionWheelSource` 等纯 Win32 资产）
    - `native/src/d3d11/`（占位目录，M3 填充）
    - `native/src/host/`（占位目录，M3 填充）
  - 清理根 `CMakeLists.txt` 与 `cmake/`：删除 JUCE FetchContent、`JuceVst3Commands.cmake`、macOS 选项，统一命名空间 `canton::*` 与 CMake 目标。
- [x] **清理原 `arrange_juce` 并归位 `native/src/runtime/`**：
  - 将无 JUCE 或仅薄胶水的编排资产迁入 `native/src/runtime/`（`CantonRuntime`、`RearrangeHost`、`ScriptEventDispatcher`、`RuntimeSessionState`、`ScenePipelineState`、`FramePlanner`、`FramePumpDriver`、`VBlankSource`、`PackageRuntimeSource`、`RuntimePackageLoader`、`RuntimePackageBinder`、`AppResolver`、`Diagnostics*`、`ErrorScreenModel`、`InputTextSession`、`TextInputMutationSink`），剥离 JUCE 头文件依赖。
  - 删除纯 JUCE GUI/IME/Pointer 适配残渣（`TextInputOwner`、`TextInputLayoutModel`、`InteractionStateOwner` 的 JUCE 壳、`PlatformWheelInput_windows.cpp` 的 JUCE 胶水）。
  - `UiPackage`、`DevServerClient`/`LiveModuleClient`、`PainterResources` 仅剥离 JUCE 残留并清理接口归位，**不强行拼凑过渡实现**（M3 按 Windows 原生依赖正式实装）。
- [x] **解除核心层两个进程级全局单例**：
  - `FontRegistry`（含 `preloads_` 预加载计数）由 `shared()` 改为按宿主/运行时实例持有。
  - `NativePainterRegistry` 由 `global()` 改为按宿主/运行时实例持有。
- [x] **命名空间与目录一一对应**：`core/`、`quickjs/`、`runtime/`、`win32/` 分别对应 `canton::core`、`canton::quickjs`、`canton::runtime`、`canton::win32`；顶层 `canton::` 只留给 `native/include/canton/` 的公开 SDK（分层与依赖方向见 [batch2 ADR 001](../adr/batch2/1：Native模块分层、依赖方向与命名空间.md)）。
- [x] **跨层工具下沉 `core`**：日志与单调时钟移入 `core/`，`win32/` 不再引用 `runtime/`；控制台着色移入 `win32/ConsoleLog`，由宿主启动时打开。
- [x] **QuickJS-NG 必选**：清除 `CANTON_WITH_QUICKJS_NG` 条件编译。
- [x] **清除非 Windows 分支**：去掉 `_WIN32` 条件编译的 POSIX 分支与 `if(WIN32)` 构建守卫。

- [x] **Modifier 原生协议表改名**：`@canton/shared` 的 `modifierSchema` 改为 `modifierNativeProtocol`，C++ 生成表改为 `ModifierNativeProtocol.h/.inc`，脚本改为 `sync:modifier-protocol` / `verify:modifier-protocol`；措辞由“schema / 白名单”统一为“Modifier 原生协议表 / 准入字段”。

- [x] **framework 目录分层**：`values/`、`native/`、`runtime/`、`animation/`、`draw/`、`layout/`、`modifier/`、`bridge/`、`arrangable/`、`app/`；原生协议改用自身的跨边界形状，消除全部跨目录循环与运行期循环导入。
- [x] **分层约束测试**：新增 `tests/runtime/package-layers.test.ts`，检查包依赖方向、compiler 与 framework 的层序，以及各包零循环导入（分层规则见 [batch2 ADR 002](../adr/batch2/2：TS包分层、依赖方向与命名.md)）。

- [x] `cpp_tests/` 改名为 `native-tests/`。

## 备份：已退役的旧产品测试用途

- `cmake-presentation` 原来主要校验产品元数据、图标资源与插件清单如何接入 CMake 目标。
- `pack-report` 原来主要校验打包报告里的产物位置、大小、路径和旧备份提示。
- `packing` 原来主要校验如何定位、暂存和替换旧产品产物，以及交付失败时如何保护上一次结果。
- `adopt-ui-hint` 原来主要校验接管已有 UI 工程时缺少类型配置是否会给出提示。
- `config-cli` 原来主要校验旧配置命令的扫描、应用、冲突选项和退出码。
- `dev-command` 原来主要校验旧开发命令如何传递退出码、取消和清理失败。
- `setup-build-dev` 的旧构建和启动部分原来主要校验分范围构建、产物有效性及各风味的构建和启动顺序。
- `verify-npm-registry-package` 原来主要通过已安装的 CLI 校验从 registry 获取指定版本后能否跑通旧工程工作流。
- `framework-admission` 的版本列表、自定义和依赖建议用例原来主要校验三种版本来源都在进入后续厂商问答前完成准入及确认。
- `framework-admission` 的创建取消用例原来主要校验旧入口会禁选缺少版本契约的条目，并在取消时保持目标目录为空。
- `command-result` 的旧同步扫描用例原来主要校验各扫描结果如何映射到 CLI 退出码，并保持宿主进程退出码。
- `entry-environment` 的旧同步和创建入口用例原来主要校验非 TTY 调用在读取工程或访问 registry 前就被拒绝。
- `terminal-session` 的旧同步帮助用例原来主要校验子命令帮助会进入会话停屏并保留成功退出码。
- `terminal-session` 的旧同步参数用例原来主要校验未知选项会进入会话停屏并保留失败退出码。
- `terminal-session` 的创建取消用例原来主要校验 Ctrl+C 和 Esc 都会完成取消收尾，并在用户按回车后交还终端。
- `project-initializer` 的模板类型检查用例原来主要校验新建工程的 CTA 模板能引用 PNG/SVG 资源，并通过隔离的类型检查。
- `project-initializer` 的 5 个图标用例原来主要校验外部 PNG 图标的只读验证与复制、同路径图标的直接引用、图标冲突和无效 PNG 的拒绝、中途取消后保留准确失败记录，以及确认后目标冲突和 assets 链接不会写到外部目录。
- `framework-resilience` 的原生源码预检用例原来主要校验 CLI 托管 Framework 仓库时，在配置构建树前用 git 检查仓库可达与版本 tag，并在报错里隐去凭据。
- `framework-origin` 的本机仓库用例原来主要校验本机 Framework 仓库覆盖的优先级和相对路径解析，以及未托管或与本地源码目录覆盖并存时的拒绝。
- `setup-service` 的源码预检用例原来主要校验预检失败时先于 UI 安装阻止全部动作，且只在需要配置构建树时才联网检查。
- `entry-environment` 的平台服务用例原来主要校验平台服务工厂对非 Windows 平台的二次拒绝。
- `canton_focus_input` 原来主要校验焦点搜索与提交、焦点生命周期、滚入可见、Lazy 按需导航，以及输入框的 IME、撤销、剪贴板、多行、多击选择和 QuickJS 焦点桥接。
- `canton_fonts` 原来主要校验字体选择、字体表读取、自带字体族登记、默认与系统字面、伪粗斜体渲染、斜体溢出，以及字体代际变化后的重排与管线接线。
- `canton_frame_submission` 原来主要校验无帧时的语义 Owner、输入几何与退休、滚轮累计、指针移动屏障、手动 VBlank、宿主资源失败与被动绘制、帧边界重载、最终发布及失败提交回滚。
- `canton_live_server` 原来主要校验连接真实 Live DevServer 后的模块快照首载、热更新、探针回传与重载请求。
- `canton_m3_draw` 原来主要校验绘制准备、变换与 Z 序、变换后的点击区、输入框绘制顺序、渐变圆角、阴影等效果、图片与位图缓存、Native Painter，以及 CTA 绘制夹具的像素结果。
- `canton_m3_layout_boundary` 原来主要校验无效布局值的拒绝、`matchParentSize` 等父布局数据边界，以及 CTA 布局夹具中有限重复动画的尺寸交付。
- `canton_m3_lazy` 原来主要校验 Lazy 四种容器、可变尺寸、key 锚点、缓存与原子提交，以及重排前后 Input 选区和 IME 组合态的保留。
- `canton_painter_resources` 原来主要校验 Live 资源的 origin 与 URL 边界、PNG/SVG 解码、HTTP 诊断、预算与超时、资源退休，以及内联资源和 Dist 包根语义。
- `canton_rearrange_runtime` 原来主要校验 CTA、Vite、QuickJS 与原生端到端的值阶段、参数、计算值、内容、身份复用与退休，并输出 Gallery 帧耗时与分配基准。
- `canton_retained_paint` 原来主要校验文本资源、输入几何、em 与行高、发布片段的复用与裁剪、输入与发布的生命周期，以及变换溢出的两级裁剪。
- `canton_scroll_input` 原来主要校验滚轮轴选择、单轴与交叉轴路由、同轴边界移交、精确滚动与归一化单位、目标锁定与失效、手势与惯性、平滑器，以及真实回调与手动帧发布。
- `canton_ui_package` 原来主要校验 Dist 包挂载、摘要与清单及引擎身份和格式校验、包内图片与字体解码、脚本加载后的首个事务，以及协议不匹配时的拒绝。
- `canton_viewport_runtime` 原来主要校验视口与内容尺寸、滚动范围、响应式回传以及宿主绘制链路。
- 上述 C++ 测试删除时一并删除只服务于它们的 `UiPackageFixture.h` 与 `tests/fixtures/fonts`。
- 本清单与上文出现的 `m3_draw.cpp`、`canton_m3_draw`、`canton_m3_layout_boundary`、`canton_m3_lazy` 是已删除文件的原名，其中的 `m3` 是 Arrange 时期的里程碑编号，与 Canton 的里程碑无关；保留原名以便在 Git 历史中检索。
