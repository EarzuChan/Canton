# M1 任务清单：品牌更名、Native 统一与大清场

承接 [ROADMAP.md](ROADMAP.md#m1品牌更名native-统一与大清场) 与 [ADR 009](../adr/009-宿主加载规矩、Native统一结构与扩展交付.md)。

> **本期原则**：**代码干净优先于强行可编可跑**。属于后续里程碑的缺口（Win32/D3D11、WIC 图像解码、WinSock/WinHTTP Live 客户端、ZIP `UiPackage`、新 CLI 业务链路）直接清干净并留白，**绝不造过渡假桩**；仅保持原本就完全独立的纯逻辑层（`packages/` TS 侧、`native/src/core/`、`native/src/quickjs/`）、非缺口区的编译/类型检查不红，作为更名防手滑的安全网。

---

## 1. 仓级配置、品牌更名与版本归零

- [ ] 清理根目录 `package.json` 中的非标准注释，根包名与脚本命令统一改为 `canton`。
- [ ] `arrange.version.json` 迁为 `canton.version.json`，版本与协议号归零重启：`frameworkVersion: "0.1.0"`、`cliVersion: "0.1.0"`、`frameworkInternalProtocolCode: 1`、`cliCompatibility: 1`。
- [ ] `packages/*` 全部更名为 `@canton/{shared,reactivity,compiler,framework,vite-plugin}`，`cli/` 更名为 `@canton/cli`；同步 `scripts/version-contract.ts`、`scripts/build-internal-packages.ts`、`scripts/pack-npm-package.ts` 等脚本契约。
- [ ] 全局标识符与类型声明收口：`types/arrange-globals.d.ts` → `types/canton-globals.d.ts`、`globalThis.__ARRANGE_NATIVE__` → `__CANTON_NATIVE__`、`__ARRANGE_HOT_*` → `__CANTON_HOT_*`、`ARRANGE_*` → `CANTON_*`、`.arrange/` → `.canton/`、`Arrange*` → `Canton*`（保留 `Arrangable` 与 `Rearrange`）。
- [ ] 清理 `scripts/` 中对已删除 `demo/ui-src` 与 `arrange_juce_runtime_smoke` 的残留引用。

## 2. DSL、字节码与 UI 包后缀迁移

- [ ] 编译器（`packages/compiler`）与 Vite 插件（`packages/vite-plugin`）：
  - 单文件后缀由 `.sfa` 统一改为 **`.cta`**（含解析、缓存、HMR、SourceMap、离线类型检查 `checkCtaProject`）。
  - 模板指令前缀由 `a-*` 改为 **`c-*`**（`c-if`、`c-else-if`、`c-else`、`c-for`、`c-bind`；同步清理 `a-slot:*`）。
  - Dev 虚拟路径与协议标识切换为 `/@canton/modules`、`/@canton/entry`、`canton:import*`。
- [ ] UI 包与字节码标识：
  - 清单文件名由 `arrange-ui.json` 改为 **`canton-ui.json`**，字节码模块后缀由 `.aex` 改为 **`.cbc`**，协议版本对齐 `1`。
  - 同步更新 `tests/fixtures/**` 中所有 `.sfa` 示例文件与 `tests/runtime/**` 引用。

## 3. 旧修饰器打掉与音频残留清理

- [ ] **全链路连根清除旧 CPU 模糊（ADR 006）**：
  - 删除 `packages/framework/src/modifier.ts` 的 `M.blur` / `M.backdropBlur`、`packages/shared/src/modifierSchema.ts` 对应项，并重新生成 C++ `ModifierSchema.inc`。
  - 删除 C++ `EffectKind::Blur` / `EffectKind::BackdropBlur` 及 `Repaint` 中对应的旧 CPU 模糊扩散分支与旧测试用例（`m3-draw.test.ts`、`m3_draw.cpp`、`repaint_region.cpp`）。
- [ ] **先行打掉公开父布局特权 Modifier（为 ADR 002 铺路）**：
  - 从公开 `Modifier` 类与编译器 `codegen.ts` 快捷链列表中移除 `M.align()`、`M.weight()`、`M.matchParentSize()`。
  - **保留**底层 `ParentData` 协议字段、C++ `ParentDataModifierSemantics` 与 `LayoutTree`/`MeasurePolicy` 布局实现（供 M2 布局 Handle 直接复用）。
  - 清理受影响的 2 处测试夹具（`tests/fixtures/m3-lazy/LazyApp.cta`、`tests/fixtures/m3-layout/LayoutApp.cta`）中对旧公开方法的调用，更新 `tests/runtime/public-api.test-d.ts` 断言旧入口已移除。
- [ ] **清除音频插件残留**：
  - 清理 `packages/framework/src/native.ts` 中的 `NativeHostFormat`、`NativeHostInfo`、`NativeTransport`、`NativeInterop*` 与 `packages/framework/package.json` 死导出 `./interop`。
  - 泛化 `packages/framework/src/dataSource.ts` 的 `DataSourceKind`（去掉写死的 `'meter' | 'waveform' | 'spectrum'`）。
  - 清除 C++ 侧残留的 `Interop.h`、`QuickJsInterop` 引用与已删除测试项（`arrange_interop*`、`arrange_juce_runtime_smoke`）。

## 4. Native 统一结构、去 JUCE 化与拆单例

- [ ] **统一目录与 CMake 结构**：
  - 撤销 `native/arrange_core`、`native/arrange_quickjs`、`native/arrange_juce` 三工程拆分，整合为单一 `native/`：
    - `native/CMakeLists.txt`
    - `native/include/canton/`（预留给后续 `canton-sdk` 公开头文件）
    - `native/src/core/`（保持零 Win32 / D3D11 依赖）
    - `native/src/quickjs/`（含 `canton_ui_bytecode` 工具与 `ModifierSchema.inc`）
    - `native/src/runtime/`（收纳原 `arrange_juce` 中可复用的宿主编排资产）
    - `native/src/win32/`（先收纳 `WindowsPrecisionWheelSource` 等纯 Win32 资产）
    - `native/src/d3d11/`（占位目录，M3 填充）
    - `native/src/host/`（占位目录，M3 填充）
  - 清理根 `CMakeLists.txt` 与 `cmake/`：删除 JUCE FetchContent、`JuceVst3Commands.cmake`、macOS 选项，统一命名空间 `canton::*` 与 CMake 目标。
- [ ] **清理原 `arrange_juce` 并归位 `native/src/runtime/`**：
  - 将无 JUCE 或仅薄胶水的编排资产迁入 `native/src/runtime/`（`CantonRuntime`、`RearrangeHost`、`ScriptEventDispatcher`、`RuntimeSessionState`、`ScenePipelineState`、`FramePlanner`、`FramePumpDriver`、`VBlankSource`、`PackageRuntimeSource`、`RuntimePackageLoader`、`RuntimePackageBinder`、`AppResolver`、`Diagnostics*`、`ErrorScreenModel`、`InputTextSession`、`TextInputMutationSink`），剥离 JUCE 头文件依赖。
  - 删除纯 JUCE GUI/IME/Pointer 适配残渣（`TextInputOwner`、`TextInputLayoutModel`、`InteractionStateOwner` 的 JUCE 壳、`PlatformWheelInput_windows.cpp` 的 JUCE 胶水）。
  - `UiPackage`、`DevServerClient`/`LiveModuleClient`、`PainterResources` 仅剥离 JUCE 残留并清理接口归位，**不强行拼凑过渡实现**（M3 按 Windows 原生依赖正式实装）。
- [ ] **解除核心层两个进程级全局单例**：
  - `FontRegistry`（含 `preloads_` 预加载计数）由 `shared()` 改为按宿主/运行时实例持有。
  - `NativePainterRegistry` 由 `global()` 改为按宿主/运行时实例持有。

## 5. CLI 最小清理（完整重造留 M8）

- [ ] 移除 `205dbfe` 遗留的 4 处悬空导入（`Adopt`、`MacPlatformService`、`MacBundleSigner`）。
- [ ] 删除 CLI 中 `darwin` / macOS 分支与 `.icns` / `PosixProcessGroup` 残留。
- [ ] 完成 CLI 基础品牌更名（`@canton/cli`、`.canton`、`CANTON_*`），**不求旧音频业务命令可运行（反而**不能运行**才是对的）**（M8 整块重造）。

- [ ] 全仓检索确认零遗留 `arrange` 品牌标识、零 JUCE 依赖、零 Audio Interop 残留、零 macOS 兼容代码。
- [ ] `modifier-schema` 同步校验通过（TS 与 C++ `ModifierSchema.inc` 一致）。

- [ ] 验收完成后，按主人要求撰写第一版反映新骨架的 `docs/ARCHITECTURE.md`。
