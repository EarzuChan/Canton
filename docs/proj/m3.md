## 0. 已定口径

- **窗口**：单窗口，只做显示、随窗口缩放重新布局、关闭。鼠标、滚轮、键盘、`Input` 打字、剪贴板、光标形状全部属 M4。
- **密度固定 1 倍**：1dp 等于 1 物理像素。进程清单仍声明 Per-Monitor V2，避免系统把窗口位图拉伸发糊；高分屏上内容偏小属预期。把缩放比交给脚本的通道和 `WM_DPICHANGED` 属 M4。
- **入口不变**：夹具继续用 `createApp(App).mount()`，窗口客户区就是布局视口。`appBuilder`、`<App>`、`<Window>` 属 M4，本期不提前造。
- **宿主制品**：本期出两份，都是 `/MT`、`CANTON_ENABLE_NATIVE_EXT=0`：`canton-host-dev.exe`（`CANTON_ENABLE_DEV=1`）和 `canton-host.exe`（`CANTON_ENABLE_DEV=0`）。`EXT=1` 的两份属 M7。条件编译的两条铁律照 ADR 009 执行。
- **加载规矩**：三种策略 `lfd`、`live`、`dist` 的行为照 ADR 009。Dev 宿主读下表的环境变量；Dist 宿主写死 `dist`，二进制里不含任何 `CANTON_DEV_*` 解析、Live 客户端和诊断浮层。

  | 环境变量 | 含义 | 缺省 |
  | --- | --- | --- |
  | `CANTON_DEV_SOURCE` | 加载策略：`lfd`、`live`、`dist` | `lfd` |
  | `CANTON_DEV_SERVER` | Live DevServer 地址 | `http://127.0.0.1:9178` |
  | `CANTON_DEV_DIST` | 开发期覆写 Dist 包位置，目录或 ZIP | 随包位置 |
  | `CANTON_DEV_READY_FILE`、`CANTON_DEV_READY_TOKEN` | 首帧成功后把令牌写进该文件 | 不写 |

- **随包 Dist 的位置**：宿主 exe 同目录下的 `ui/`（目录包）或 `ui.zip`（ZIP 包），两者同时存在时报错。
- **错误屏与恢复**：没有按键。恢复靠改文件触发的热更新和 Live 自动重连。
- **分层**：`d3d11`、`win32` 只依赖 `core`，由 `host` 装配到 `runtime`；`CANTON_ENABLE_DEV` 只出现在构建接线和 `host/`、`quickjs/` 的顶层装配入口。
- **第三方依赖**：系统自带 API 能做的（WinHTTP、BCrypt、WIC、DirectWrite）不引依赖。做不了的（如 ZIP 解压、SVG）可以引入小型 C/C++ 依赖，或把小份代码直接并入仓库。要求单一用途、许可证宽松；经 FetchContent 引入的在 `cmake/NativeDependencies.json` 钉死到 commit，并入仓库的注明出处和许可证。`THIRD_PARTY_NOTICES.md` 主人标了勿动，不要改，新增依赖列在“施工笔记”里由主人登记。
- **无头回归**：
  - 测试程序直接链接渲染库，离屏渲染、读回像素、存成 PNG，不经宿主参数。无头只是不开窗，显卡照常可用。
  - 每个用例跑两档适配器：WARP 出基线（各机器结果一致）；硬件显卡复跑，按容差和基线比。机器没有可用的硬件显卡时跳过这一档，并在输出里写明。
  - 基线图进 Git。每次运行的输出图和差异图写到 `.canton/verification/`（已被 Git 忽略）。
  - 基线图就是主人验收看的截图。新增或更新基线要在交付说明里逐张列出；更新基线必须是显式操作，不能在普通测试运行里自动覆盖。
  - 容差数值按实测定，写进“施工笔记”。
- **像素基线里的文字只用自带的测试字体**，不依赖系统字体。M1 删掉的测试字体和生成脚本可以找回（`git show 369be40^:tests/fixtures/fonts/<文件>`），文件名里的旧品牌要改。系统字体回落只做不比像素的断言。
- **测试时钟**：无头用例由测试程序给时间，不读真实时钟，动画在指定时刻取帧。
- **内置着色器**在构建期编译成 DXBC 嵌进二进制，运行期不依赖 `d3dcompiler_47.dll`。运行期编译留给 M5 的用户着色器。
- **每帧整幅重绘**：按脏区局部呈现本期不做（见文末移交）。
- **`drawNative`** 的后端实现属 M7。本期渲染器遇到它不绘制，记一条诊断日志。

## 4. 文本

- [x] **DirectWrite 排版**实现 `TextMeasurer`：换行、最大行数、省略、单行；行与分段几何、首行和末行基线、墨迹范围。光标位置、点击落点、选区矩形经 `TextLayoutService` 现有接口算得对。

### 已定的实现决定（理由）

- **加载模型**：`runtime/LoadPolicy.h` 的 `AppSourceConfig`（策略、DevServer 地址、随包目录、Dist 覆写）由宿主装配时给 `PackageRuntimeSource`；`AppResolver` 只负责定位和挂载 Dist。Live 客户端经工厂注入，Dist 宿主不给工厂，也就不链接 Live 库。
- **Live 不可用时**：`lfd` 有 Dist 就加载 Dist 并弹不合并的警告提示，没有 Dist 与 `live` 一样进错误屏；客户端在后台持续重连，连上后自动取新快照切回 Live。
- **渲染输入的内容类型放 core**：`core::BitmapContent`（预乘位图）和 `core::VectorContent`（按像素尺寸栅格化的接口）。解码在 `runtime`，渲染在 `d3d11`，两边只在 core 的类型上见面。
- **形状抗锯齿用解析梯度，不用屏幕导数**：实测屏幕导数在恰好压线的像素上硬件与 WARP 结果不同（最大通道差 112），改为由变换的雅可比解析求像素宽度后两档最大差 2。直角矩形按两轴覆盖率相乘，轴对齐时就是精确面积。
- **描边口径对齐 Compose，分两类**（2026-11-22 续做时主人定）：`border` 修饰器对所有形状向内；Canvas 的 `drawRect`、`drawRoundRect`、`drawOval` 描边对所有形状以轮廓为中线，与 `drawPath` 描边一致。`core::drawOpBounds` 的外扩量随之对齐。
- **SVG 改用 lunasvg**（主人定）：nanosvg 不支持 `clipPath`、`use`、`mask`。我们自己的安全预检（禁外部引用、DOCTYPE、实体，视口必须有效）照留。
- **像素基线的测试字体改为子集 Noto**（主人定）：点阵字形全是直角方块，测不到曲线轮廓的抗锯齿，截图里也难认。实际取的是 Noto Sans（拉丁，google/fonts 提交 `8b0a1d0f`，2.015 版）的可变字体，实例化出常规 400、粗体 700、斜体 400 三个字面，只留可打印 ASCII、不换行空格与省略号，族名改为 Canton Test Sans（Noto 没有保留字体名，OFL 允许改名再发布），许可证 `OFL.txt` 随字体放。没有用 Noto Sans SC：它没有斜体字面，留下真斜体才能继续验“选中了哪个字面”；SC 是 CFF 轮廓，也没法和拉丁字形合进一个字体。夹具文字都是 ASCII，没有中文。生成脚本 `tests/fixtures/fonts/generate.py` 下载钉死的源文件并校验 SHA-256。
- **阴影在像素着色器里解析求**：水平方向 erf 闭式、垂直方向 16 点数值积分，支持分角圆角与椭圆；标准差小于 0.25 按 0.25 处理。
- **裁剪**：无旋转的矩形裁剪用剪刀矩形（四边取整到最近像素，同旧实现）；第一层圆角/椭圆裁剪在像素着色器里解析求；嵌套的圆角裁剪、路径裁剪、旋转后的矩形裁剪画进与目标同尺寸的 R8 掩码。
- **路径**：CPU 精确面积覆盖率光栅化成掩码（见将写的 ADR）；描边由自写的描边器出轮廓再按非零规则填充，尖角限制 4。
- **文字**：`IDWriteTextLayout` 负责换行、省略和系统回落，字面由 Canton 选定后以“只含一个字面的自定义集合 + 该字面自己的字重/字形”交给 DirectWrite，避免它再做匹配和模拟。字形经 `IDWriteGlyphRunAnalysis`（灰度、不做网格对齐、四分之一像素相位）进 2048² 的 R8 图集；伪粗体取字形轮廓加 `syntheticBoldStroke` 描边后自行栅格化，伪斜体把错切并进字形变换。图集满了整体清空重来。
- **测试字体**：`tests/fixtures/fonts/CantonTestSans-*.ttf`，生成脚本同目录。旧字体的字形是空心方块，截图里认不出字，改成 5×7 点阵字形（仍是原创、三个字面前进量各不相同）。【~~主人之前备注：如果需要用真字，可以读取机子带的微软雅黑等（无需捆绑进项目，机子一般都会有）；要捆绑可以延续之前的“截取必要字集的 Noto”方案~~】
