# 004 原生窗口外观、自绘标题栏与任务栏身份

日期 2026-11-20。

## 背景

承接 [ADR 001](001-Windows用户态目标、应用入口与受管工程.md) 与 [ADR 003](003-App与Window模型、Owner与模态.md)，本篇确定以 Windows 11 为主要兼容目标的原生窗口的外观形态、能力开关、`WindowState` 几何与 DPI 约定、自绘标题栏及系统三键协作契约，以及任务栏固定身份、标题和图标的归属关系。

## 窗口外观形态与原生能力

不向 TS 暴露原始 `WS_*` / `WS_EX_*` 位掩码，也避免用单一 `undecorated` 布尔值把“自绘标题栏”与“纯无边框窗”混为一谈，改为按正交维度声明：

- **装饰模式 `chrome`（默认 `'system'`）**：
  - `'system'`：标准 Win32 系统标题栏与边框，自动具备系统三键、圆角、阴影、Aero Snap 与 Snap Layout。
  - `'customTitleBar'`：保留标准重叠窗框架，通过 `WM_NCCALCSIZE` 吃掉默认顶栏并配合 DWM 保留原生圆角、阴影、最小化/最大化动画、Aero Snap 和边缘缩放，客户区从窗口顶部 `(0, 0)` 开始由应用自绘。最大化时，宿主必须在 `WM_NCCALCSIZE` 中自动缩回系统外扩的边框边距，防止内容边缘被屏幕裁切。
  - `'frameless'`：纯 `WS_POPUP` 无边框窗口，适用于启动页、悬浮条或按像素透明/异形窗口。
- **能力与角色 Props**：提供正交的 `resizable`、`minimizable`、`maximizable`、`closable`、`alwaysOnTop` 与 `role`（`'standard' | 'utility'`，默认 `'standard'`）。`'utility'` 映射 `WS_EX_TOOLWINDOW`：在 `'system'` 下呈现单关闭键细标题栏，且默认不进入任务栏与 Alt-Tab 列表。
- **Win11 背景材质与圆角**：支持声明式 `backdrop`（`'none' | 'mica' | 'micaAlt' | 'acrylic'`）与 `cornerPreference`（`'default' | 'round' | 'roundSmall' | 'square'`）。框架内部按系统能力探测（如 Win11 22621+ `DWMWA_SYSTEMBACKDROP_TYPE`）并在不支持的环境下静默回退到常规背景，不要求业务按 Windows 版本号写条件分支。`'frameless'` 显式设置 `round`/`roundSmall` 可获得 DWM 圆角与阴影；若窗口启用按像素任意透明或异形轮廓，则不再套用 DWM 系统圆角与材质，改由应用自行绘制。

## `WindowState` 几何形态与 Per-Monitor DPI

- **Per-Monitor V2 DPI**：宿主进程声明 `PER_MONITOR_AWARE_V2`。每个窗口独立响应 `WM_DPICHANGED`，更新自身 [ADR 003](003-App与Window模型、Owner与模态.md) 约定的窗口级 `Density` 并应用系统建议矩形，避免跨不同缩放比显示器拖拽时抖动。
- **尺寸与位置单位**：`WindowState` 中的 `size`、`minSize`、`maxSize` 统一采用**逻辑客户区 `dp`**，保证布局根视口在 `'system'` 与 `'customTitleBar'` 下语义一致。`position` 首阶段提供语义预设（`'platformDefault'`、`'centerScreen'`、`'centerOwner'`，默认 `'platformDefault'`）；后续若开放或回写具体窗口坐标，一律采用 Windows **物理虚拟屏幕像素**，避免多屏混搭 DPI 时坐标系失真。
- **形态与可见性**：`placement` 区分 `'normal'`、`'minimized'`、`'maximized'`（占满当前屏工作区）与 `'fullscreen'`（无边框覆盖整屏并记录还原态）；`visible` 控制原生显示/隐藏，不卸载组合树。

## 自绘标题栏、拖拽区与系统三键协作

纯 Win32 用户态下无公开 API 能在隐藏系统标题栏的同时保留 DWM 自绘三键。因此在 `'customTitleBar'` 下，标题栏与最小化/最大化/关闭按钮统一由应用自绘（上层后续可提供标准 Win11 样式现成组件），并通过 [ADR 002](002-Slot句柄与父布局数据.md) 与 [ADR 003](003-App与Window模型、Owner与模态.md) 确立的 `WindowHandle` 作用域 Modifier 上报非客户区语义：`draggableArea()`、`nonDraggableArea()` 与 `captionButton('minimize' | 'maximize' | 'close')`。

- **`WM_NCHITTEST` 严格按 5 级优先级判定**：
  1. 窗口四边与四角原生缩放热区（`resizable && placement === 'normal'`，含顶部 `HTTOP` 热区）；
  2. `captionButton(...)`（返回 `HTMINBUTTON` / `HTMAXBUTTON` / `HTCLOSE`，其中悬停 `HTMAXBUTTON` 由 Windows 11 原生触发 Snap Layout 分屏浮层）；
  3. 常规可交互节点与显式 `nonDraggableArea()`（带点击、拖拽、滚轮或输入能力的子节点自动返回 `HTCLIENT` 让位，无需在拖拽区内手动挖空）；
  4. `draggableArea()`（返回 `HTCAPTION`，获得原生零延迟拖拽、双击最大化/还原、Aero Snap 与右键系统菜单）；
  5. 其余区域返回 `HTCLIENT`。
- **非客户区消息托管与防闪烁**：宿主必须拦截命中三键的 `WM_NCLBUTTONDOWN` / `WM_NCLBUTTONUP`（不交 `DefWindowProc`，防止 Win32 复古按钮覆盖闪现），将三键区域的 `WM_NC*` 消息桥接进 Canton 指针与 `InteractionState` 管线以驱动自绘按钮的悬停/按压视觉；点击松开时由宿主直接执行最小化、最大化/还原或发起 `WM_CLOSE`（继续走 `onCloseRequest`），业务侧不重复绑定点击动作。三键语义自动受 `minimizable`、`maximizable`、`closable` 开关联动约束。

## 任务栏身份、图标与标题

任务栏图标、标题及固定（Pin）行为按三层数据源分工：

1. **静态包层（未启动与固定图标）**：由 `canton.project.yaml` 声明应用名、默认图标与 **AUMID**（`AppUserModelID`）。Dist 打包（基于 [ADR 001](001-Windows用户态目标、应用入口与受管工程.md) 与 [ADR 009](009-宿主加载规矩、Native统一结构与扩展交付.md) 所述预编译宿主）必须产出独立命名的 `<AppName>.exe` 并写入对应 PE 图标与版本元数据，避免多个 Canton 应用在未启动或固定时共用同一通用宿主身份。
2. **进程 / `<App>` 层**：宿主启动早期调用 `SetCurrentProcessExplicitAppUserModelID` 绑定同一 AUMID，使运行中窗口归并到已固定的任务栏图标并按应用分组，同时以应用图标作为窗口未显式传 `icon` 时的兜底。
3. **`<Window>` 层**：每个窗口的 `title` 与可选 `icon` 均同步给 Win32（在 `'customTitleBar'` 与 `'frameless'` 下同样同步），决定该窗口在任务栏悬浮预览卡片及 Alt-Tab 中的标题与图标。

任务栏显隐默认规则与 `owner`、`role`、`visible` 联动：`role === 'standard'`、无 `owner`（含 `owner="none"`）且 `visible === true` 的窗口默认出现在任务栏分组与悬浮预览中；`'utility'` 工具窗、有 `owner` 的子窗口及隐藏窗口默认不上任务栏；同时保留可选 `showInTaskbar` 供显式覆写。
