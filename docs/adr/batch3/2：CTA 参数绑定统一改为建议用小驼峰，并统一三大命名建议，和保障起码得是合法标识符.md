# 002 CTA 参数绑定统一改为建议用小驼峰，并统一三大命名建议，和保障起码得是合法标识符

日期 2026-11-24。

> 本文已将[批次1的002](../batch1/2：Slot句柄与父布局数据.md)中参数名连字符归一化的约定，以及[批次1的009](../batch1/9：宿主加载规矩、Native统一结构与扩展交付.md)中的 `c-bind` 指令废弃。

## 背景

Canton 没有 HTML/DOM 大小写不敏感的包袱，此前沿用隐式 `camelize`、`.camel` 修饰符以及 `c-bind`，导致同一标签上 `:horizontalArrangement` 与 `&row-handle` 混写、进入模板作用域又要写回 `rowHandle`，并让编译器和重排作用域背负多余的转换与对象展开机制。

## 决定

- **底线是合法 JS 标识符，小驼峰是推荐约定**：参数声明、静态与动态传参（`:`）、`<Slot>` 出口实参、槽位取参（`&`）以及槽位名（`#` / `<Slot name>`）一律原样按字面名字处理，不做连字符转换，且必须是合法 JS 标识符。推荐统一写小驼峰（如 `:onCloseRequest`、`&appHandle`），但不强加风格正则，`snake_case` 等其它合法标识符照常放行。
- **字段名和局部绑定各按所在位置校验**。字段名共用 ECMAScript `IdentifierName` 的 Unicode 字符规则，因此 `中文` 和 `class` 可以作字段名，`×` 会报错。`&` 生成的解构形参交给 TypeScript 解析器按模块语法校验。`&class` 会因局部变量名不合法而报错，可以写 `&class="classValue"`。
- **废除指令修饰符与 `c-bind`**：连根移除 `.camel` 等指令修饰符解析，废除 `c-bind`（含与 `:name` 重复的 `c-bind:name` 及整包对象展开 `c-bind="obj"`，同时禁止无参数名的 `:=""`）。
- 确立**模板三层命名分工**的建议（非代码级强制约束，但十分建议）：标签强制精确大驼峰（`PascalCase`）；控制指令独占 `c-xxx` 连字符写法（仅 `c-if`、`c-else-if`、`c-else`、`c-for`）；契约与标识符层（传参、取参、槽位指定）统一推荐小驼峰合法标识符。

## 为什么不选别的

- **用正则强制限定小驼峰**：大小写风格属于书写约定，编译器不当风格警察；守住“合法 JS 标识符”这根语法底线，能让字段声明与传参遵循同一套规则，局部变量按绑定位置的语法校验。
- **只限制 `&` 取参而不限制 `:` 传参**：Arrangable 对标函数而非 HTML 属性字典，`defineProps` 字段在内部模板同样当标识符读取，`<Slot :param>` 与 `&param` 也互为上下游；两边统一要求合法标识符，才不会出现传得出却接不出的割裂。
- **保留 `c-bind="obj"` 整包展开**：Canton 对齐 Compose，通用横切能力收敛在 `:modifier` 链，成组配置显式传对象参数（如 `<DynamicArrangable :is="..." :props="obj" />`），不需要为 DOM 式属性透传保留重排作用域上的动态对象展开开销。

## 代价

- 不能在 TS 里用引号声明 `'kebab-name'` 这类非标识符参数或槽位名。
- 不能把一个对象直接展开成多个组件参数，需显式绑定对应参数或设计对象类型参数。
