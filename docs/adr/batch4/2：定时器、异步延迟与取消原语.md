# 002 定时器、异步延迟与取消原语

日期 2026-11-27。

## 背景

Canton 在单个 QuickJS-NG VM 中执行业务脚本，此前仅提供 `performance.now()`，缺少定时回调、异步延迟与通用取消机制。防抖、Toast 自动关闭、倒计时、轮询与超时重试都是日常界面刚需，既要兼容常见纯 TS 工具库，也要避免组件卸载或 HMR 重载后残留幽灵回调。

## 决定

- **宿主驱动原生定时队列，全局挂载精简标准原语**：由 C++ 宿主事件循环统一维护高精度定时队列并按时唤醒脚本（不阻塞渲染帧；HMR 重载或 VM 销毁时整体清空）。启动期在 `globalThis` 挂载 `setTimeout`、`clearTimeout`、`setInterval`、`clearInterval`、`queueMicrotask` 以及轻量 `AbortController` / `AbortSignal`。定时器仅接受函数参数，不支持字符串代码求值。
- **框架层提供作用域感知封装与 `delay`**：`@canton/framework` 导出 `useTimeout` 与 `useInterval`（在组件或 `effectScope` 内自动绑定 `onScopeDispose`，卸载时自动取消），以及非阻塞异步等待 `delay(ms, signal?)`（传入 `AbortSignal` 取消时立即释放底层定时器并 reject `AbortError`）。
- **分期落地**：暂定 M6 先完成宿主底层定时队列与 TS 侧完整 API；M7 在 `canton-sdk` 中为 Native 扩展补齐对称的 `ctx.timers()`（返回 RAII 取消句柄，扩展卸载自动失效），复用同一套宿主定时调度。

## API 契约

### 1. `globalThis` 标准原语（启动期由宿主自动挂载）

```ts
declare function setTimeout<TArgs extends unknown[]>(
    fn: (...args: TArgs) => void,
    delayMs?: number,
    ...args: TArgs
): number
declare function clearTimeout(id?: number): void

declare function setInterval<TArgs extends unknown[]>(
    fn: (...args: TArgs) => void,
    intervalMs?: number,
    ...args: TArgs
): number
declare function clearInterval(id?: number): void

declare function queueMicrotask(fn: () => void): void

declare class AbortSignal {
    readonly aborted: boolean
    readonly reason: unknown
    onabort: (() => void) | null
    throwIfAborted(): void
    addEventListener(type: 'abort', listener: () => void, options?: { once?: boolean }): void
    removeEventListener(type: 'abort', listener: () => void): void
    static abort(reason?: unknown): AbortSignal
    static timeout(ms: number): AbortSignal
}

declare class AbortController {
    readonly signal: AbortSignal
    abort(reason?: unknown): void
}
```

- **大体行为**：
  - `setTimeout` / `setInterval` 共享同一自增正整数 ID 空间；`clearTimeout` / `clearInterval` 传入无效或已撤销 ID 时静默忽略。
  - 仅接受函数回调，传入字符串或非函数抛 `TypeError`；`delayMs` / `intervalMs` 缺省、为负或 `NaN` 时按 `0` 处理。
  - `setInterval` 在单次回调返回后再安排下一拍，不因回调耗时积压连环重入；单次回调抛错按未处理异常上报，不影响其他定时项。
  - `AbortController.abort(reason?)` 幂等，首次调用锁定 `aborted = true` 与 `reason`（缺省为 `name === 'AbortError'` 的 `Error`）并按注册顺序同步触发监听器；`AbortSignal.timeout(ms)` 到期时以 `name === 'TimeoutError'` 的 `Error` 自动取消。
  - HMR 重载或 VM 销毁时，宿主一次性撤销旧会话全部未到期定时器。

### 2. `@canton/framework` 作用域定时与异步延迟

```ts
export interface TimerHandle {
    readonly active: boolean
    cancel(): void
}

export function useTimeout(fn: () => void, delayMs: number): TimerHandle
export function useInterval(fn: () => void, intervalMs: number): TimerHandle
export function delay(ms: number, signal?: AbortSignal): Promise<void>
```

- **大体行为**：
  - `useTimeout` / `useInterval`：若在组件 `setup` 或 `effectScope` 内调用，自动挂接 `onScopeDispose` 在卸载时调用 `cancel()`；在作用域外调用亦可正常使用并手动 `cancel()`。`useTimeout` 执行完毕或取消后 `active` 为 `false`；`cancel()` 幂等。
  - `delay(ms, signal?)`：非阻塞等待指定毫秒后 resolve；若传入的 `signal` 已取消，立即 reject `signal.reason` 且不建定时器；等待中取消则立刻撤销底层定时器、解绑监听并 reject `signal.reason`；正常到期后自动解绑监听。`delay` 不隐式绑定组件生命周期，按需传 `signal` 控制取消。

### 3. M7 Native 侧预留（`canton-sdk`）

- 暂定 M7 通过 `ctx.timers()` 提供 `setTimeout` / `setInterval`，返回 RAII `TimerHandle`（析构或扩展卸载自动取消），底层复用 M6 宿主定时队列。

## 为什么不选别的

- **不挂载 `globalThis` 定时器，交给用户自备 polyfill**：QuickJS 本身没有事件循环与时钟中断，纯 JS 无法 polyfill；且大量纯 TS 逻辑库默认依赖 `setTimeout` / `queueMicrotask` / `AbortController`，缺失会导致无谓的生态报错。
- **异步等待命名为 `sleep`**：`sleep` 在系统编程里容易让人联想到阻塞当前线程；`delay` 更准确表达非阻塞挂起，也与 Compose / Kotlin 协程的命名心智保持一致。

## 代价

- 宿主消息循环需维护定时唤醒与取消账本，在无窗口托盘驻留或 0 窗错误屏兜底期间同样需要正确驱动与清理。
- 内置 `AbortController` / `AbortSignal` 仅覆盖标准取消语义（`abort`、`aborted`、`reason`、`addEventListener`/`removeEventListener`），不实现完整的 DOM `EventTarget` 体系。
