# 001 专注 D3D11 单后端、图形能力感知与渐进降级

日期 2026-11-27。

> 本文承接 [batch1 ADR 006](../batch1/6：D3D11渲染管线、HLSL着色器与离屏层.md)，明确无显卡驱动或低性能桌面环境下的渲染边界与降级机制。

## 背景

在无显卡驱动、虚拟机或远程桌面（RDP）环境下，D3D11 会回退至 Microsoft Basic Render Driver / WARP；在 LiberNT，也会有很多没打驱动而需要内建软渲染机制的情况。实测表明，WARP 在常规简单 UI 上内存与流畅度均可接受，但多 Pass 高斯模糊、离屏背景层与液态玻璃等重着色器会让 CPU 耗时急剧上升。故这次要考量环境的检测和对设计降级提供建议的 API，以及做一些力所能及的优化。

## 决定

- **专注 D3D11 + DirectComposition 单后端，不自建软件渲染器**：无可用硬件显卡时继续依赖系统 WARP 兜底，保证呈现链路与图形语义唯一。
- **底层管线不做静默硬降级**：D3D11 渲染器在 WARP 下仍维持完整功能（着色器、离屏层、滤镜链全部可用）。用户或自绘组件若明确强上重特效，框架照常执行、不替其静默阉割；这同时也保住无头像素回归继续用 WARP 产出 100% 完整基线。
- **顶层响应式能力感知（`provide`）**：`<App>` 顶层通过 `GraphicsEnvironmentKey` 向下注入响应式只读 `GraphicsEnvironment`（包含后端、适配器名、是否软件渲染/硬件加速、是否 RDP、Windows 系统透明效果与动画开关，以及派生的建议档位 `full` / `reduced`）。运行期发生 `DEVICE_REMOVED` 重建退回 WARP 或收到系统设置变更时自动更新；子树可再次 `provide` 局部覆写（例如应用自己的“省电/强制特效”设置）。
- **内建/官方效果组件按感知主动降级**：如 `@canton/kyant-glass` 的 backdrop 液态玻璃等效果层订阅 `GraphicsEnvironmentKey`，在 `reduced` 档下主动跳过离屏背景录制、多 Pass 模糊与折射着色器，回落为高对比度半透明或实色表面配细描边，兼顾可用性与观感。
- **WARP 无损内存瘦身**：`d3d11::Renderer` 检测到软件适配器时，在不改变渲染结果的范围内采取更克制的资源策略（缩短空闲离屏 RT 池回收周期、R8 字形/路径图集按较小初始尺寸按需扩容）。

## API 契约

导出自 **`@canton/framework/ui`**（与 `DensityKey` 并列），由 `<App>` 顶层 `provide`：

```ts
export type GraphicsTier = 'full' | 'reduced'

export interface GraphicsEnvironment {
    readonly backend: 'd3d11'
    readonly adapterName: string          // 适配器描述名，如 "Microsoft Basic Render Driver"
    readonly isSoftwareRenderer: boolean  // 是否 WARP / Basic Render Driver
    readonly hardwareAccelerated: boolean // !isSoftwareRenderer
    readonly isRemoteSession: boolean     // GetSystemMetrics(SM_REMOTESESSION)
    readonly systemTransparency: boolean  // Windows 系统“透明效果”开关
    readonly systemAnimations: boolean    // SPI_GETCLIENTAREAANIMATION
    readonly recommendedTier: GraphicsTier
}

export const GraphicsEnvironmentKey: InjectionKey<GraphicsEnvironment>
```

- **行为约定**：对象内部由响应式状态驱动，读任意字段自动建立依赖；`recommendedTier` 在 `hardwareAccelerated && !isRemoteSession && systemTransparency` 为真时取 `'full'`，否则取 `'reduced'`；运行期设备丢失重建或系统设置变更时自动更新；子树可再次 `provide(GraphicsEnvironmentKey, ...)` 局部覆写。

## 为什么不选别的

- **接入 Blend2D / ThorVG 另建 CPU 软渲染后端**：会迫使 Win32 呈现层在 DirectComposition 与 GDI `BitBlt` / `UpdateLayeredWindow` 之间分叉；带来永久性的双后端维护税、绘制语义漂移与额外回归基线；且把软渲染库编入预编译宿主会让绝大多数有硬件显卡的用户白白承担分发体积。
- **底层在 WARP 下自动硬禁用 Shader / 模糊**：一方面会破坏 WARP 无头像素回归基线，另一方面简单跳过着色器会让依赖其底色的组件直接透明或对比度崩坏，体验不如由上层按感知做语义级回落。

## 代价

- 无显卡驱动环境下仍需承担 D3D11 / WARP 的基础内存开销，高于纯 CPU 软光栅化方案，但在现代桌面内存口径下仍远轻于 Webview 方案。
- 第三方或业务自定义重特效组件需主动读取 `GraphicsEnvironmentKey` 才能在低配环境获得优雅降级，否则仍按完整特效消耗 CPU。
