# 005 路径用 CPU 精确覆盖率光栅化

日期 2026-11-22。

## 背景

[batch1 ADR 006](../batch1/6：D3D11渲染管线、HLSL着色器与离屏层.md) 定了 D3D11 管线，把路径用覆盖率掩码还是三角化留给实现。路径包括 Canvas 的 `drawPath`（非零与奇偶填充、描边的端点与连接）、`clipPath`、嵌套的圆角裁剪，以及伪粗体的字形描边。无头回归要求 WARP 逐像素一致、硬件档按小容差比对。

## 决定

- 路径在 CPU 上展平成折线（曲线细分段数按局部到设备的放大倍数定），按精确面积求每个像素的覆盖率，得到 8 位掩码，存进 R8 图集（单块超过 512 像素的单独建纹理），像素着色器只采样掩码乘画刷。
- 描边由自写的描边器出轮廓多边形，再按非零规则填充；尖角限制为线宽的 4 倍。
- 掩码按路径对象、去掉整数平移后的变换和描边参数缓存，同一条路径平移整数像素（如滚动）不重新光栅化。
- 形状（矩形、圆角、椭圆）不走这条路，在像素着色器里解析求覆盖率；像素宽度由变换的雅可比解析求，不用屏幕导数。

## 为什么不选别的

- **GPU 三角化加 MSAA**：抗锯齿质量取决于采样数，奇偶规则要模板缓冲两遍，硬件与 WARP 的光栅化规则在压线像素上结果不同，基线难以逐像素一致。
- **GPU 上的距离场或解析覆盖率**：自相交、奇偶规则和描边连接在着色器里很难做对，代价是大量调试与特例。
- **借 Direct2D 画进共享纹理**：多一套设备与同步，D2D 的抗锯齿在硬件与 WARP 上也不保证一致，且裁剪、变换状态要跨两套 API 对齐。
- **屏幕导数（`ddx`/`ddy`）求形状像素宽度**：实测在恰好压线的像素上硬件与 WARP 差到 112，改为解析求后两档最大差 2。

## 代价

- 路径的首次光栅化在 CPU 上，复杂路径在大放大倍数下会慢；动画中不断变形的路径每帧都要重算。
- 掩码占图集空间，图集满了整体清空重来，之后用到的字形与路径按需重新光栅化。

【主人备注：如果以后为了性能，可以下放到 GPU，没说一定要都像素完美相似，能抗锯齿就行】
