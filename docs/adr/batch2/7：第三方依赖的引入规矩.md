# 007 第三方依赖的引入规矩

日期 2026-11-22。

## 背景

M3 需要 ZIP 解压和 SVG 渲染，系统 API 做不了。此前 Native 只依赖 QuickJS-NG。

## 决定

- **系统 API 能做的不引依赖**：HTTP 用 WinHTTP，摘要用 BCrypt，位图解码用 WIC，文字用 DirectWrite。
- **做不了的引小型 C/C++ 依赖**：单一用途、许可证宽松（MIT、zlib、BSD 一类）。经 FetchContent 只取源码，不执行依赖自己的构建脚本，由 Canton 挑要编译的文件；在 `cmake/NativeDependencies.json` 钉死到 commit，`cmake/Dependencies.cmake` 校验检出的 commit，`scripts/native-source-cache.ts` 从同一份清单预取到缓存。直接并入仓库的小份代码要注明出处和许可证。
- **M3 引入的两个**：miniz 3.1.0（MIT，只编 `miniz_tinfl.c` 做 deflate 解压）；lunasvg 3.5.0（MIT，连同它仓库里自带的 plutovg 编成一个静态库，关掉系统字体与从文件加载字体）。SVG 的安全边界（禁外部引用、DOCTYPE、实体，视口必须有效）由我们自己在解析前检查，不依赖库的行为。
- **测试资产**同样钉死来源：测试字体的生成脚本下载钉死提交的 Noto Sans 并校验 SHA-256。
- `THIRD_PARTY_NOTICES.md` 由主人登记，执行者在里程碑笔记里列出新增依赖、版本和许可证。

## 为什么不选别的

- **nanosvg**：起初用它，但不支持 `clipPath`、`use`、`mask`，`clipPath` 在图标里常用。
- **resvg**：质量最好，但要引入 Rust 工具链。
- **Direct2D 的 SVG 支持**：要 D2D 设备与 Windows 10 1703 以上的接口，支持范围不明，且把解码拉到渲染设备上，不适合在资源线程里解成与设备无关的内容。
- **依赖自带的 CMake**：会带进安装规则、示例与可选功能，选项随上游变化，不如自己列源文件可控。

## 代价

- 上游升级要手工改清单里的 ref 与 commit，并核对要编译的文件列表。
- plutovg 里有改自 FreeType 光栅器的代码，适用 FreeType License，需要在文档里致谢；stb 部分是 MIT 或 Public Domain 二选一。
- CLI 的清单类型目前只声明了 `quickjs_ng`，另两个由脚本直接读，M8 重造 CLI 时收进来。
