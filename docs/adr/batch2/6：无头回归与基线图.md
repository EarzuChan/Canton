# 006 无头回归与基线图

日期 2026-11-22。

## 背景

M3 的窗口只显示、没有输入，主人验收靠截图。需要一套能在任何 Windows 机器上稳定复现、又能发现硬件差异的像素回归。

## 决定

- **测试程序直接链接渲染库**（`canton_render_regression`），离屏渲染、读回像素、存 PNG，不经宿主参数。两类用例：直接喂绘制指令验渲染器；从 `.cta` 夹具经 Vite 构建、UI 包挂载、QuickJS、core 到离屏画面（`runtime::SceneHost` + `dist` 策略 + Dist 覆写）。
- **两档适配器**：WARP 出基线，要求逐像素一致；硬件显卡复跑，每通道差不超过 2、超出的像素不超过 0.05%。机器没有可用的硬件显卡时跳过这一档并在输出里写明。
- **基线图进 Git**，放 `native-tests/baselines/`（不在会被测试脚手架整目录拷走的 `tests/fixtures/` 下）。运行的输出图和差异图写 `.canton/verification/render/`。基线只在 `pnpm baseline:update` 时写入，普通运行缺基线就失败，不自动补。
- **时间由用例给**：虚拟时钟 16 毫秒一拍，动画在指定时刻取帧；后台资源加载用“真实时间里一段时间没有新工作”判定安定。分步操作经夹具里隐藏输入框的提交槽发指令。
- **文字只用自带测试字体**：子集化的 Noto Sans（常规、粗、斜三个字面，族名改为 Canton Test Sans，OFL），不依赖系统字体。系统字体回落只做不比像素的断言。

## 为什么不选别的

- **硬件出基线**：不同显卡、驱动的光栅化与混合有细微差别，基线换台机器就不成立。
- **只跑 WARP**：发现不了只在硬件上出现的问题（如屏幕导数在压线像素上的差异）。
- **宿主截窗口**：要开窗、要等合成，结果受 DWM 和缩放影响，自动化里不稳。
- **点阵测试字体**：字形全是直角方块，测不到曲线轮廓的抗锯齿，截图里也难认。

## 代价

- 基线图随渲染行为变化要显式更新并逐张看图，改一处共用的绘制（如描边口径、字体）会牵动多张图。
- 字体子集只有 ASCII 与少数符号，测不到 CJK 在像素层面的表现。
