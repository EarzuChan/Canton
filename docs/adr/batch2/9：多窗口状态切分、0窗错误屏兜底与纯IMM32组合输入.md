# 009 多窗口状态切分、0 窗错误屏兜底与纯 IMM32 组合输入

日期 2026-11-23。

> 本文补齐了 [batch1 ADR 003](../batch1/3：App与Window模型、Owner与模态.md)、[004](../batch1/4：原生窗口外观、自绘标题栏与任务栏身份.md) 在 M4 落地的细节口径。

## 背景

运行时从单树单视口转向“单 QuickJS VM 驱动多原生窗口”后，需要界定窗口几何与外观属性分别归属声明式参数还是双向状态对象、尚无可见窗口时的启动与热更错误如何呈现、Windows 桌面输入法如何以最低复杂度接入自绘文本输入，以及开发期窗口调试工具如何在编译期与发布宿主物理剥离。

## 决定

- **唯一入口与 `WindowState` / `<Window>` 职责切分**：
  - 全仓移除 `createApp` 与显式 `.mount()`；入口模块统一默认导出 `appBuilder(Root).build()` 产出的不可变应用定义，由宿主在模块求值完成后自动启动。
  - 外观、能力与拓扑关系（`title`、`icon`、`visible`、`minSize`、`maxSize`、`owner`、`modality`、`chrome`、`role`、`resizable`/`minimizable`/`maximizable`/`closable`、`alwaysOnTop`、`showInTaskbar`、`backdrop`、`cornerPreference`、`onCloseRequest`）归 `<Window>` 声明式参数单向驱动。
  - 用户与脚本双方都会改写的几何形态（`size` 客户区 `dp`、`position` 预设或物理虚拟屏幕坐标、`placement`）及只读运行期观测（`focused`、`dpiScale`）与动作（`activate()`、`requestClose()`）归 `createWindowState()`。同一 `WindowState` 同时绑定多个活跃 `<Window>` 直接报错；窗口卸载后保留最后几何快照供复开复用。
  - `<Window>` 建立独立画区作用域并按窗独立提供 `DensityKey` 与 `FocusManagerKey`；`<Window>` 对祖先布局透明，画区外挂载 `<Layout>` 或跨窗混用 `WindowHandle` 非客户区修饰器直接报错。桥接层仅用私有 `WeakMap` 维护进程内单调不复用的私有整数窗口身份，不向业务脚本暴露裸 `HWND` 或窗口 ID。
- **提交边界末窗退出与 0 窗错误屏兜底**：
  - `<App :exitOnLastWindowClosed>` 仅在一次完整重排事务提交收尾后、且当前会话曾成功打开过至少一个窗口而活跃窗口数降为 `0` 时触发有序退出；同一重排事务内“销毁旧窗并打开新窗”不触发退出。
  - 启动装配报错、Live DevServer 不可达且无随包回退、入口模块异常，或运行期挂起时若当前没有任何可见 `<Window>`，宿主自动建立单兜底窗展示错误屏并保持重连恢复能力；一旦恢复并挂载可见应用窗口即自动收起兜底窗。已有可见窗口时直接在原窗口展示错误屏。
- **纯 Win32 IMM32 与显式 `compositionRange` 组合原语**：
  - 桌面文本输入只接 `imm32.lib`（`WM_IME_*`、`ImmGetCompositionStringW`、`ImmSetCandidateWindow`、`ImmNotifyIME`、`ImmAssociateContext`），不引入 TSF COM `ITextStoreACP`。
  - 仅当窗口焦点落在启用且非 `readOnly` 的 `<Input>` 上时关联 `HIMC`，其余时刻 `ImmAssociateContext(hwnd, nullptr)`，避免非输入态按键唤出输入法。
  - `core::TextInputState` 移除平台隐式编辑补丁，改为显式维护 UTF-8 `compositionRange` 与子句目标标记（区分目标转换段粗下划线与普通未定段细下划线）。组合预编辑期间仅更新原生叠层、不触发脚本 `onValueChange`；`GCS_RESULTSTR` 上屏时才触发 `onValueChange` 并将整次组合合为单条 Undo（支持同一消息先结果上屏再续写新预编辑串）。鼠标移位、失焦、`Esc` 或外部受控覆写主动调 `ImmNotifyIME(..., CPS_CANCEL)`。
- **窗口级调试控制器经装配入口注入**：
  - `F5` 重载、`F8` 帧率徽标、`F9` / `Shift+F9` `DiagnosticsOverlay` 与错误屏点击重试、`Ctrl+C` 复制诊断全文统一封装于 `DevAssembly.cpp` 注入的 `DevWindowController`；`DistAssembly.cpp` 留空，配合链接器 `/OPT:REF` 使 `canton-host.exe` 物理不含任何调试热键、`DiagnosticsOverlay`、`DiagnosticsHud` 与 Live 代码，`CANTON_ENABLE_DEV` 不进入 `core`/`win32`/`d3d11`/`runtime`/`quickjs`。

## 为什么不选别的

- **把 `size` / `placement` 也做成 `<Window>` 受控参数**：用户拖拽缩放边框或双击标题栏最大化时每帧都在改尺寸，若强求业务每次经回调手写受控回传，既繁琐又极易因回传延迟制造窗口抖动回弹。
- **引入 TSF COM（`ITextStoreACP`）**：自绘 UI 没有复杂富文本无障碍文档流诉求时，TSF 状态同步与文档锁重入成本极高；现代 Windows 10/11 系统输入法与主流第三方中文输入法对标准 IMM32 + `CFS_EXCLUDE` 候选框定位兼容成熟稳定。
- **0 窗报错直接静默退出或弹窗 `MessageBox`**：静默退出在开发期无从排查，模态 `MessageBox` 会阻塞消息循环导致 Live 热修恢复失效；复用同一渲染管线的单兜底错误窗可无缝承接后续热恢复。

## 代价

- IMM32 不向输入法提供输入框外的周围上下文词句预测，也不支持输入法反向读取非组合区的超长文档内容；对桌面常规单行与多行 `<Input>` 足够。
- `WindowState` 内部需记录最近一次来自原生的几何快照以消除“原生几何变更 → 响应式通知 → 冗余反向 `SetWindowPos`”回声。
