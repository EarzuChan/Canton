# 001 Windows 用户态目标、应用入口与受管工程

日期 2026-11-19。

## 项目基线与平台

Canton 基于 Arrange 改造独立开发而来，：Canton 初始提交 `a880da0` 源于 Arrange `2dc0a95` 的快照。Arrange 时期的设计沿革见原项目相关 ADR 文档（自 026 之前的篇目）。Canton 自本篇起记录自身的架构决策。

Canton 面向 Windows 原生桌面。首阶段交付普通用户态应用，开发和验收环境为 Windows 11【关于 LiberNT 的事项按下不表，这一点是主人留给自己的暗号】。

TS / `.cta` 与 QuickJS 承载应用声明和响应式逻辑。C++ 负责原生窗口、重排执行、布局、输入和绘制。图形后端定为 D3D11 + DXGI，着色器语言采用 HLSL。运行时 Shader、Windows 原生窗口样式，以及自定义标题栏与系统最小化、最大化和关闭按钮的协作，列为框架能力目标。

## 应用入口与窗口声明

用户应用统一从 TS 入口启动，默认入口为 `app/src/main.ts`。入口选定应用根组件，可通过 `appBuilder` 装配插件与应用级服务，并默认导出 `appBuilder(MyApp).build()` 的结果。`build()` 产出应用定义，由原生宿主加载并启动。Live 与 Dist 使用同一个入口契约。

应用根 `.cta` 声明 `<App>` 与 `<Window>`。窗口声明随应用组合更新，每个窗口的内容拥有独立布局根。`App` 通过默认 Slot 提供 `appHandle`，调用方可用 `&app-handle` 显式接收。Slot 参数及 Handle 的具体语义见 [ADR 002](002-Slot句柄与父布局数据.md)。

## 工程层次与宿主

| 路径 | 职责 |
| --- | --- |
| `app/` | TS / `.cta` 应用项目，包含源码、依赖清单和锁文件。 |
| `native/` | 可选的原生扩展源码（编译为独立扩展 DLL），用于接入 C/C++ 或其他原生库、调用 Windows 能力，以及注册高性能绘制、测量或布局实现。 |
| `canton.project.yaml` | 随仓库提交的工程配置，记录框架版本、扩展开关、构建与发布元数据，允许覆盖默认 TS 入口路径。 |
| `canton.local.yaml` | 按需生成的本机配置，记录工具链路径、本地开发加载策略或构建缓存位置等机器相关信息，由 Git 忽略。 |

所有工程统一使用框架提供的官方预编译宿主（按是否启用 `native/` 选用基础版或可扩展版，具体矩阵与加载规矩见 [ADR 009](009-宿主加载规矩、Native统一结构与扩展交付.md)）。需要原生扩展时，用户仅需将 `native/` 编译为独立扩展 DLL 挂载，无需重编宿主；两种形态共用相同的 TS 入口和启动契约。

## CLI 与升级

Canton CLI 是 Windows 上受管工程的正式入口。`sync` 负责核对并同步工程配置、框架版本、UI 工具链以及启用 `native/` 时的原生扩展构建接线。在纯 TS 与启用 `native/` 扩展之间切换可以作为已知工程状态间的受管变更。Canton CLI 的命令范围移除 `adopt`。

CLI 与框架沿用兼容码。目标框架超出 CLI 的兼容范围时，`sync` 在写入工程前停止，提示先升级 CLI。对受支持的升级路径，`sync` 按受管文件的归属预览并应用迁移。需要用户决定或手工处理的冲突应在应用迁移前报告。
