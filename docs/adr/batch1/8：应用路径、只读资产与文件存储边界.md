# 008 应用路径、只读资产与文件存储边界

日期 2026-11-20。

## 背景

承接 [ADR 001](1：Windows用户态目标、应用入口与受管工程.md)、[ADR 005](5：WindowsShell集成、托盘与启动唤醒.md) 与 [ADR 007](7：CMake构建、宿主交付与Native增强接口.md)，在明确不以 Windows 注册表存放应用业务数据的前提下，本篇确定随包只读资产、应用专属目录、用户标准目录、外部文件访问，以及 TS 与 `native/` 双侧存储的粒度与职责边界。

## 存储粒度克制

框架核心与预编译宿主**不内置数据库（如 SQLite）与重型偏好设置（Prefs）框架**，只提供权威的路径解析与精简的文件 I/O 原语（含原子写入）：

- 重型持久化、本地数据库查询及索引交由 `native/` 扩展或后续可选旁包承担，不拖大预编译宿主包体；
- 偏好设置待实际需要时以旁包形态叠在应用目录与原子写原语之上，内核保持精简。

## 只读资产 VFS 与真实磁盘路径二分

- **应用随包资产（`assets`）保留只读 VFS**：Live 模式读工程目录、Dist 模式读打包资源容器，物理位置不固定，必须通过只读抽象接口访问而不暴露真实磁盘路径。TS 侧沿用异步 `assets.readText` / `readBytes` / `exists`；同时向 `native/` 侧开放宿主上下文同步直读（`ctx.assets()`），免除原生模块经 JS 中转拷贝。
- **其余所有目录与外部文件一律采用 Windows 真实磁盘路径**：不套虚拟 URI 协议，保证 `native/` 第三方库直接可用，也便于与 `LaunchRequest`、系统文件对话框及后续外部文件拖放无缝衔接。
- **用户标准目录**：`downloads`、`documents`、`desktop`、`pictures`、`music`、`videos` 必须经 Win32 `SHGetKnownFolderPath` 实时解析，严禁拼接环境变量或硬编码 `C:\Users`。
- **外部文件**：首阶段面向普通用户态桌面应用，遵循操作系统自身文件 ACL 权限，不引入路径白名单配置；原生层内部统一采用 UTF-16 宽字符并兼容长路径。

## 应用专属目录与透明重定位

应用专属目录精简为 **`dataDir`**（持久化应用数据，配置、缓存与日志子结构由应用自行组织）与 **`tempDir`**（短期临时文件）两个，按需懒创建，不预设多余空目录。

引入**启动期透明重定位**机制，仅作用于应用专属目录（用户标准目录与外部文件始终为真实系统路径），由宿主在启动时只读确定，对 TS 与 `native/` 完全透明且字节级一致，解析优先级如下：

1. **显式重定位根目录**：Live 开发期由 CLI 默认定向至工程构建/临时目录（或由 `canton.local.yaml` 与自动化测试覆写），避免调试数据污染系统 `%LOCALAPPDATA%`；
2. **绿色便携模式**：发行配置启用便携形态（或检测到约定便携标记）时，透明落盘至程序同级数据目录，业务与 `native/` 代码无需修改；
3. **默认常规安装态**：`dataDir` 落于 `SHGetKnownFolderPath(FOLDERID_LocalAppData)\<app.id>`，`tempDir` 落于 `GetTempPath2W()\<app.id>`。

## TS 侧与 `native/` 侧文件 I/O 分工

两边共用同一套底层路径解析与安全文件实现，但按体量与性能职责分层：

- **TS 侧（可选子模块，如 `@canton/framework/fs`）**：
  - 路径以函数形式提供（如 `paths.appData()`、`paths.downloads()`，遵循 [ADR 005](5：WindowsShell集成、托盘与启动唤醒.md) 避免在 `main.ts` 顶层挂载前求值），并附带轻量路径拼接与拆解工具；
  - 文件与目录操作（`readText` / `readBytes` / `writeText` / `writeBytes` / `exists` / `stat` / `readDir` / `mkdir` / `remove` / `rename` / `copy`）全部运行于宿主后台 I/O 线程池，**全异步不阻塞 UI 与渲染帧**；写入提供可选 `atomic`（默认 `false`，写重要配置或工程文件时显式开启，经同目录临时文件、刷盘与 `ReplaceFileW` / `MoveFileExW` 防止写坏）；
  - 明确定位于日常中小文件管理，不重造完整 Node.js `fs`。
- **`native/` C++ 侧**：
  - 通过宿主上下文 `ctx.paths()` 直接返回与 TS 一致的 `std::filesystem::path`，并复用底层宽字符安全读写与原子写助手（`canton::fs`），不另造笨重的流式 I/O 封装；
  - 大文件流式读写、目录监控（`ReadDirectoryChangesW`）、音视频/压缩包解析及数据库操作等重型非 UI 文件任务，均由 `native/` 直接配合标准 C++ / Win32 API 与 [ADR 007](7：CMake构建、宿主交付与Native增强接口.md) 的异步线程高效处理，避免劳累 QuickJS。

## 后续边界

外部文件拖放（`IDropTarget`）与系统文件对话框（`IFileOpenDialog` / `IFileSaveDialog`）交付的真实路径直接接入本篇模型，具体交互 API 留待后续专题；偏好设置与数据库支持按需以旁包或 `native/` 扩展形态演进。
